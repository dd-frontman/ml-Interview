# Инструкции для Codex: ML Interview Workspace

## Цель проекта

Развивать русскоязычную базу знаний по Python, математике и Machine Learning для личного обучения, быстрого повторения и подготовки к работе ML Engineer. Сохранять существующую структуру VitePress, соглашения о контенте и проверки проекта.

## Обучение через примеры (Example-Driven Learning)

**При создании и существенном обновлении учебных материалов используй практико-ориентированное объяснение.** Предпочитай движение от понятной задачи к необходимой теории, а не длинную абстрактную теорию до первого примера.

Для каждой подходящей темы:

1. **Мотивация и задача.** В одном-двух абзацах объясни, зачем это нужно и какую конкретную проблему решаем.
2. **Минимальный работающий пример.** Покажи небольшой, воспроизводимый пример на Python или, для математической темы, простой числовой пример. Укажи ожидаемый результат и необходимые зависимости, если они есть.
3. **Теория на основе примера.** Последовательно объясни понятия, формулы и ключевые строки кода, связывая их с показанной задачей. Не пропускай важные предпосылки и ограничения.
4. **Усложнение.** По возможности добавь один реалистичный вариант или пограничный случай, который показывает, как принцип работает за пределами простого примера.
5. **Самостоятельная практика.** Предложи 1–3 задания от простого к сложному. Не раскрывай полное решение сразу, если материал рассчитан на самостоятельную работу; можно дать подсказку или вынести решение в отдельный раскрываемый раздел.
6. **Типичные ошибки.** Покажи распространённые заблуждения, баги и способы проверки результата.
7. **Краткое повторение.** Заверши компактными выводами и, когда уместно, подсказками о том, что полезно вспомнить перед собеседованием.

### Правила качества

- Примеры должны быть точными, исполняемыми и соответствовать изложенной теории. Не придумывай результаты экспериментов или метрики.
- Для ML-примеров по возможности фиксируй random seed, избегай утечки данных, разделяй обучение и оценку, объясняй выбор метрик и ограничения модели.
- Давай определения новых терминов простым русским языком, сохраняя общепринятые названия библиотек и технических понятий.
- Не превращай каждую заметку в огромный учебник: подбирай глубину по сложности темы. Для справочных страниц и коротких определений допускается сокращённая структура.
- Предпочитай небольшие самостоятельные примеры, которые можно проверить без тяжёлой инфраструктуры.
- Если тема продолжает ранее изученную, связывай её с уже знакомым материалом и предлагай короткий практический «вход» в задачу.
- Сохраняй оригинальные мысли, корректные объяснения и существующие требования проекта при редактировании; не переписывай страницы без необходимости.
- Следуй правилам `README.md` относительно `docs/`, frontmatter, русского языка, генерации метаданных и проверок.

**Критерий готовности:** читатель может объяснить идею своими словами, воспроизвести пример и решить хотя бы одну небольшую вариацию задачи без копирования готового решения.
