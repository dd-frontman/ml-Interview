## Что такое `pickle` {#chto-takoe-pickle}

`pickle` — модуль стандартной библиотеки Python для сохранения объектов Python и их последующего восстановления.

```python
import pickle
```

Устанавливать его через `pip` не нужно.

Представим, что программа создала сложный объект. Пока программа работает, объект находится в оперативной памяти. После завершения программы память освобождается, поэтому объект исчезает.

`pickle` позволяет:

1. преобразовать объект в последовательность байтов;
2. записать эти байты в файл;
3. позже прочитать файл;
4. восстановить объект Python.

Такое сохранение данных между разными запусками программы называют **длительным**, или **постоянным хранением объекта**.

```text
объект Python → pickle → байты в файле
байты из файла → pickle → восстановленный объект Python
```

Сам процесс преобразования объекта в сохраняемый формат называется **сериализацией**. Обратное восстановление называется **десериализацией**.

## Сохранение через `pickle.dump()` {#sokhranenie-cherez-pickle-dump}

Рассмотрим состояние игры:

```python
import pickle

game_state = {
    "player": "Alex",
    "level": 5,
    "inventory": ["sword", "potion"],
}

with open("game_state.pkl", "wb") as file:
    pickle.dump(game_state, file)
```

`pickle.dump()` получает два аргумента:

- объект, который нужно сохранить;
- открытый файловый объект.

Файл открывается в режиме `"wb"`:

- `w` означает запись;
- `b` означает бинарный режим.

Бинарный режим обязателен, потому что `pickle` записывает байты, а не обычный текст.

## Почему файл не закрывается явно {#pochemu-fayl-ne-zakryvaetsya-yavno}

В примерах файл закрывается, но это делает конструкция `with` автоматически:

```python
import pickle

data = {"level": 5}

with open("data.pkl", "wb") as file:
    pickle.dump(data, file)

print(file.closed)  # True
```

Последняя строка выполняется уже после выхода из блока `with`. Значение `True` показывает, что файл закрыт.

Файловый объект является контекстным менеджером:

1. `open()` открывает файл;
2. `with` вызывает метод `__enter__()`;
3. выполняется вложенный блок;
4. при выходе вызывается `__exit__()`;
5. `__exit__()` закрывает файл.

Это сработает и при исключении внутри блока. Упрощённо `with` заменяет такую конструкцию:

```python
file = open("data.pkl", "wb")

try:
    pickle.dump(data, file)
finally:
    file.close()
```

`finally` выполняется независимо от того, завершилась запись успешно или возникла ошибка. Поэтому вариант с `with` короче и безопаснее.

Вручную вызывать `file.close()` внутри `with` не нужно.

## Восстановление через `pickle.load()` {#vosstanovlenie-cherez-pickle-load}

Теперь прочитаем сохранённый файл:

```python
import pickle

with open("game_state.pkl", "rb") as file:
    loaded_state = pickle.load(file)

print(loaded_state["player"])  # Alex
print(loaded_state["level"])  # 5
print(loaded_state["inventory"])  # ['sword', 'potion']
```

Режим `"rb"` означает чтение бинарных данных:

- `r` — чтение;
- `b` — бинарный режим.

`pickle.load()` не возвращает текст. Он восстанавливает объект Python, в этом примере — словарь со вложенным списком.

## Сохранение экземпляра собственного класса {#sokhranenie-ekzemplyara-sobstvennogo-klassa}

В отличие от JSON, `pickle` умеет сохранять многие объекты, характерные именно для Python, включая экземпляры пользовательских классов.

```python
import pickle


class Player:
    def __init__(self, name, level):
        self.name = name
        self.level = level


player = Player("Alex", 5)

with open("player.pkl", "wb") as file:
    pickle.dump(player, file)

with open("player.pkl", "rb") as file:
    loaded_player = pickle.load(file)

print(type(loaded_player) is Player)  # True
print(loaded_player.name)  # Alex
print(loaded_player.level)  # 5
```

После загрузки получен не словарь, а новый экземпляр класса `Player` с сохранёнными атрибутами.

Для восстановления Python должен иметь доступ к определению класса `Player`. В реальном проекте класс обычно находится в импортируемом модуле. Если класс удалить, переименовать или переместить, загрузка старого файла может перестать работать.

## `pickle.dumps()` и `pickle.loads()` {#pickle-dumps-i-pickle-loads}

Как и у `json`, буква `s` в названии означает работу со значением в памяти, а не прямую работу с файлом.

```python
import pickle

numbers = [1, 2, 3]
serialized = pickle.dumps(numbers)
restored = pickle.loads(serialized)

print(type(serialized))  # <class 'bytes'>
print(restored)  # [1, 2, 3]
```

Обрати внимание на различие:

- `json.dumps()` возвращает строку `str`;
- `pickle.dumps()` возвращает байты `bytes`.

| Функция | Что делает |
| --- | --- |
| `pickle.dump(object, file)` | записывает объект в бинарный файл |
| `pickle.load(file)` | восстанавливает объект из бинарного файла |
| `pickle.dumps(object)` | возвращает объект в виде `bytes` |
| `pickle.loads(data)` | восстанавливает объект из `bytes` |

## Какой объём данных может хранить `pickle` {#kakoy-obyom-dannykh-mozhet-khranit-pickle}

У `pickle` нет собственного хранилища и фиксированного лимита вроде 1 ГБ или 10 ГБ. Он только превращает объект в поток байтов. Эти байты можно:

- записать в обычный файл;
- сохранить в базе данных;
- разместить в `io.BytesIO`;
- передать по сети.

Практический максимальный размер ограничивают:

1. свободное место на диске;
2. ограничения файловой системы;
3. объём оперативной памяти;
4. структура и размер исходного объекта;
5. версия протокола `pickle`;
6. время сериализации и загрузки.

Протокол 4 и более новые протоколы рассчитаны в том числе на очень большие объекты. Но это не означает, что `pickle` удобен для файлов любого размера.

### Разница по памяти между `dump()` и `dumps()` {#raznitsa-po-pamyati-mezhdu-dump-i-dumps}

```python
pickle.dump(data, file)
```

`dump()` записывает поток сериализованных данных в переданный файл.

```python
serialized = pickle.dumps(data)
```

`dumps()` возвращает единый объект `bytes`. Эти байты целиком находятся в оперативной памяти вместе с исходным объектом. Для больших данных это может временно потребовать значительно больше RAM.

При загрузке также нужна память для восстановленного объекта:

```text
файл на диске → pickle.load() → объект в оперативной памяти
```

Размер файла и размер восстановленного объекта в RAM не обязаны совпадать. Например, компактный бинарный файл после загрузки может превратиться в структуру Python, занимающую заметно больше памяти.

### Как узнать размер pickle-файла {#kak-uznat-razmer-pickle-fayla}

```python
from pathlib import Path

file_path = Path("data.pkl")
size_in_bytes = file_path.stat().st_size
size_in_megabytes = size_in_bytes / 1024 / 1024
```

`st_size` содержит фактический размер файла в байтах.

`pickle` сам по себе не сжимает данные. Если важен размер, поток можно дополнительно сжать, например через `gzip`. Для больших таблиц, массивов и ML-данных часто лучше подходят специализированные форматы: Parquet, NumPy `npy`, joblib или формат конкретной ML-библиотеки.

## `pickle` сохраняет не любые объекты {#pickle-sokhranyaet-ne-lyubye-obekty}

Иногда говорят, что `pickle` может сохранить «любой объект Python». Это полезное упрощение, но буквально оно неверно.

Обычно можно сохранять:

- числа, строки и булевы значения;
- списки, кортежи, словари и множества;
- экземпляры многих пользовательских классов;
- функции и классы верхнего уровня модуля при соблюдении ограничений.

Проблемы могут возникнуть с открытыми файлами, сетевыми соединениями, локальными функциями, генераторами и объектами, связанными с внешними ресурсами.

```python
import pickle

file = open("data.txt", "w", encoding="utf-8")

try:
    pickle.dumps(file)
except TypeError as error:
    print(type(error).__name__)  # TypeError
finally:
    file.close()
```

Перед сохранением важно проверить, поддерживает ли конкретный объект сериализацию.

## Основные ограничения `pickle` {#osnovnye-ogranicheniya-pickle}

### Формат предназначен для Python {#format-prednaznachen-dlya-python}

Программа на JavaScript, Java или другом языке обычно не сможет полноценно восстановить Python-объект из pickle-файла. Для обмена между разными языками лучше использовать JSON, MessagePack, Protocol Buffers или другой согласованный формат.

### Классы и функции сохраняются по имени {#klassy-i-funktsii-sokhranyayutsya-po-imeni}

`pickle` не записывает в файл исходный код класса или функции. Он сохраняет имя модуля и полное имя объекта.

При загрузке Python должен суметь импортировать тот же модуль и найти в нём класс или функцию под прежним именем. Если класс переместить или переименовать, старый файл может перестать загружаться.

Лямбда-функции и функции, объявленные внутри другой функции, обычно нельзя надёжно сохранить стандартным `pickle`.

### `__init__()` обычно не вызывается при загрузке {#init-obychno-ne-vyzyvaetsya-pri-zagruzke}

При восстановлении экземпляра Python обычно создаёт объект и возвращает сохранённое состояние без обычного вызова `__init__()`.

Поэтому нельзя рассчитывать, что `__init__()` автоматически проверит или пересчитает загруженные данные. Для управления сохранением и восстановлением существуют специальные методы `__getstate__()` и `__setstate__()`.

### Изменение класса требует совместимости {#izmenenie-klassa-trebuet-sovmestimosti}

Если pickle-файлы должны жить долго, полезно хранить версию структуры данных. Тогда при загрузке можно преобразовать старое состояние в новое.

Без такой миграции удаление атрибута, изменение его смысла или перенос класса может сломать старые данные.

### Глубокая вложенность ограничена рекурсией {#glubokaya-vlozhennost-ogranichena-rekursiey}

Сильно вложенная или рекурсивная структура может превысить максимальную глубину рекурсии и вызвать `RecursionError`.

Самоссылочные структуры `pickle` поддерживает, но чрезвычайно глубокие графы объектов всё равно могут стать проблемой.

### Ошибка может оставить неполный файл {#oshibka-mozhet-ostavit-nepolnyy-fayl}

Если во время `pickle.dump()` встретился неподдерживаемый объект, часть байтов уже могла попасть в файл. Такой файл нельзя считать корректным.

Для важных данных безопаснее:

1. записать результат во временный файл;
2. убедиться, что запись завершилась;
3. заменить старый файл новым.

### Нет управления одновременным доступом {#net-upravleniya-odnovremennym-dostupom}

`pickle` не является базой данных. Он не решает самостоятельно:

- одновременную запись из нескольких процессов;
- блокировки;
- транзакции;
- поиск отдельных объектов;
- частичное обновление данных.

Для таких задач нужна база данных или, для простого словарного интерфейса, стоит изучить модуль `shelve`.

### Разные протоколы требуют совместимых версий Python {#raznye-protokoly-trebuyut-sovmestimykh-versiy-python}

Более новый протокол может быть неизвестен старой версии Python. Если файл должен читаться в нескольких окружениях, протокол выбирают с учётом самой старой поддерживаемой версии.

Для локального использования можно явно выбрать наиболее новый доступный протокол:

```python
import pickle

data = {"level": 5}

with open("data.pkl", "wb") as file:
    pickle.dump(data, file, protocol=pickle.HIGHEST_PROTOCOL)
```

Это может улучшить эффективность, но уменьшить совместимость со старыми версиями Python.

## Главное правило безопасности `pickle` {#glavnoe-pravilo-bezopasnosti-pickle}

::: danger Никогда не загружайте недоверенные pickle-файлы
Во время `pickle.load()` или `pickle.loads()` файл может заставить Python выполнить произвольный код. Загружайте только данные, которые создала ваша программа или другой полностью доверенный источник.
:::

`pickle` не является безопасным форматом обмена данными с пользователями, чужими сервисами или неизвестными файлами из интернета.

Для недоверенных данных обычно выбирают JSON и отдельно проверяют полученную структуру.

## JSON и `pickle`: что выбрать {#json-i-pickle-chto-vybrat}

| Характеристика | JSON | `pickle` |
| --- | --- | --- |
| Формат | текст | бинарные данные |
| Можно прочитать человеком | да | нет |
| Работает в разных языках | да | в основном только Python |
| Поддерживает пользовательские классы | не напрямую | часто да |
| Безопасно загружать без проверки источника | нужна проверка данных | нет, только доверенный источник |
| Устойчивость к изменению кода | обычно выше | может сломаться после изменения классов |

Практическое правило:

- JSON подходит для API, конфигураций, обмена данными и файлов, которые должны быть понятны другим программам;
- `pickle` подходит для временного внутреннего хранения доверенных Python-объектов;
- для долгоживущих данных важного проекта лучше использовать явную схему: JSON, базу данных или специализированный формат.

## Типичные ошибки с `pickle` {#tipichnye-oshibki-s-pickle}

### Открыть файл в текстовом режиме {#otkryt-fayl-v-tekstovom-rezhime}

```python
with open("data.pkl", "w", encoding="utf-8") as file:
    pickle.dump({"id": 1}, file)  # TypeError
```

Нужен бинарный режим `"wb"`.

### Загрузить файл из неизвестного источника {#zagruzit-fayl-iz-neizvestnogo-istochnika}

Проверки расширения `.pkl` недостаточно. Вредоносные команды могут находиться внутри сериализованных данных.

### Считать pickle-файл вечным форматом {#schitat-pickle-fayl-vechnym-formatom}

Файл может зависеть от версии Python, библиотек и структуры классов. `pickle` не стоит использовать как единственный архив важных данных без стратегии совместимости и резервных копий.

## Практическая задача {#prakticheskaya-zadacha}

Создай класс `Settings` с атрибутами `theme` и `font_size`. Затем:

1. создай экземпляр класса;
2. сохрани его в файл `settings.pkl`;
3. прочитай объект из файла;
4. выведи оба восстановленных атрибута;
5. объясни, почему файл нужно открывать в режимах `"wb"` и `"rb"`.

::: details Показать решение

```python
import pickle


class Settings:
    def __init__(self, theme, font_size):
        self.theme = theme
        self.font_size = font_size


settings = Settings("dark", 16)

with open("settings.pkl", "wb") as file:
    pickle.dump(settings, file)

with open("settings.pkl", "rb") as file:
    loaded_settings = pickle.load(file)

print(loaded_settings.theme)  # dark
print(loaded_settings.font_size)  # 16
```

`pickle` записывает байты, поэтому для записи используется `"wb"`, а для чтения — `"rb"`.

:::

## Краткая шпаргалка {#kratkaya-shpargalka}

```python
import pickle

# Объект Python -> бинарный файл
with open("data.pkl", "wb") as file:
    pickle.dump(data, file)

# Бинарный файл -> объект Python
with open("data.pkl", "rb") as file:
    data = pickle.load(file)

# Объект Python -> bytes
serialized = pickle.dumps(data)

# bytes -> объект Python
data = pickle.loads(serialized)
```

Главное правило: `pickle.load()` и `pickle.loads()` можно применять только к данным из доверенного источника.

## Краткое повторение {#kratkoe-povtorenie}

- `pickle` сериализует многие объекты Python в байты.
- `dump()` и `load()` работают с бинарными файлами.
- `dumps()` и `loads()` работают с `bytes` в памяти.
- Не каждый объект можно сериализовать.
- Изменение класса может сделать старый pickle-файл несовместимым.
- Загрузка недоверенного pickle-файла опасна.
