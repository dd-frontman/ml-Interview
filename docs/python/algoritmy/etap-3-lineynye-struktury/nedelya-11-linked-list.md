## Цель недели {#tsel-nedeli}

Научиться работать не с индексами, а со ссылками между узлами. Главная задача недели — безопасно менять эти ссылки и не терять оставшуюся часть списка.

После недели нужно уметь:

- объяснить устройство односвязного списка;
- отличить связный список от встроенного `list`;
- пройти список от головы до конца;
- изменить ссылку `next` без потери узлов;
- развернуть список;
- использовать фиктивный узел `dummy`;
- применять медленный и быстрый указатели;
- найти середину и обнаружить цикл;
- оценивать сложность операций.

## Что такое связный список {#chto-takoe-svyaznyy-spisok}

Связный список состоит из отдельных узлов. Каждый узел хранит:

1. Значение.
2. Ссылку на следующий узел.

```text
head
  |
  v
[10 | next] -> [20 | next] -> [30 | None]
```

`head` — ссылка на первый узел. У последнего узла `next` равен `None`, потому что следующего элемента нет.

## Класс узла {#klass-uzla}

```python
class ListNode:
    def __init__(
        self,
        value: int,
        next_node: "ListNode | None" = None,
    ) -> None:
        self.value = value
        self.next = next_node
```

Создадим список `10 -> 20 -> 30`:

```python
third = ListNode(30)
second = ListNode(20, third)
head = ListNode(10, second)
```

Переменные `head`, `second` и `third` содержат ссылки на объекты. Значения узлов не лежат внутри одного массива.

## Linked List и list — не одно и то же {#linked-list-i-list-ne-odno-i-to-zhe}

Встроенный Python-список `list` является динамическим массивом. Он поддерживает быстрый доступ по индексу:

```python
numbers = [10, 20, 30]
second_number = numbers[1]  # Получение по индексу занимает O(1).
```

У связного списка нет операции `head[1]`. Чтобы получить второй узел, нужно перейти по ссылке от первого:

```python
second_node = head.next
```

Чтобы получить узел с индексом `k`, нужно сделать `k` переходов. Поэтому доступ по позиции занимает `O(n)`.

## Сложность основных операций {#slozhnost-osnovnykh-operatsiy}

| Операция | Linked List | Python `list` |
| --- | --- | --- |
| Доступ по индексу | `O(n)` | `O(1)` |
| Добавление в начало | `O(1)` | `O(n)` |
| Удаление начала | `O(1)` | `O(n)` |
| Добавление после известного узла | `O(1)` | Зависит от позиции |
| Поиск значения | `O(n)` | `O(n)` |

Важное уточнение: вставка в связный список работает за `O(1)`, только если нужный узел уже найден. Если сначала нужно найти позицию, весь процесс займет `O(n)`.

## Как пройти весь список {#kak-proyti-ves-spisok}

```python
def linked_list_to_list(head: ListNode | None) -> list[int]:
    values: list[int] = []
    current = head

    while current is not None:
        values.append(current.value)
        current = current.next

    return values
```

Переменная `current` последовательно указывает на каждый узел. Сам `head` не изменяется, поэтому ссылка на начало списка остается доступной после обхода.

Если передвигать `head` напрямую, это допустимо внутри функции, но после цикла локальная переменная будет равна `None`. Для понятности обычно используется отдельная переменная `current`.

## Как вставить узел после известного узла {#kak-vstavit-uzel-posle-izvestnogo-uzla}

Пусть есть список:

```text
10 -> 30
```

Нужно вставить `20` после узла `10`.

```python
def insert_after(node: ListNode, value: int) -> None:
    new_node = ListNode(value)

    # Новый узел должен вести туда, куда раньше вел текущий.
    new_node.next = node.next

    # Теперь текущий узел ведет на новый.
    node.next = new_node
```

Порядок действий важен. Если сначала выполнить `node.next = new_node`, старая ссылка на `30` потеряется, если ее заранее не сохранить.

## Главная опасность — потерять ссылку {#glavnaya-opasnost-poteryat-ssylku}

Рассмотрим текущий фрагмент:

```text
current -> [10] -> [20] -> [30]
```

Если сразу изменить `current.next`, доступ к `[20]` и `[30]` через `current` исчезнет. Поэтому перед изменением ссылки нужно сохранить старое продолжение:

```python
next_node = current.next
current.next = previous
current = next_node
```

Эти три строки являются основой разворота списка.

## Пример 1. Разворот связного списка {#primer-1-razvorot-svyaznogo-spiska}

Было:

```text
10 -> 20 -> 30 -> None
```

Должно стать:

```text
30 -> 20 -> 10 -> None
```

```python
def reverse_list(head: ListNode | None) -> ListNode | None:
    previous: ListNode | None = None
    current = head

    while current is not None:
        # Сохраняем остаток списка до изменения current.next.
        next_node = current.next

        # Разворачиваем ссылку текущего узла назад.
        current.next = previous

        # Previous становится началом уже развернутой части.
        previous = current

        # Переходим к сохраненному следующему узлу.
        current = next_node

    # После цикла current равен None,
    # а previous указывает на новую голову списка.
    return previous
```

### Значение трех указателей {#znachenie-trekh-ukazateley}

- `previous` — уже развернутая часть;
- `current` — узел, который обрабатывается сейчас;
- `next_node` — еще не обработанный остаток.

### Пошаговый разбор {#poshagovyy-razbor}

Для списка `10 -> 20 -> 30`:

| Шаг | `previous` | `current` | `next_node` | Развернутая часть |
| --- | --- | --- | --- | --- |
| До цикла | `None` | `10` | — | Пусто |
| 1 | `10` | `20` | `20` | `10 -> None` |
| 2 | `20` | `30` | `30` | `20 -> 10 -> None` |
| 3 | `30` | `None` | `None` | `30 -> 20 -> 10 -> None` |

Каждый узел посещается один раз:

- время: `O(n)`;
- дополнительная память: `O(1)`.

## Что такое dummy node {#chto-takoe-dummy-node}

`dummy` — фиктивный узел перед настоящей головой списка.

```text
dummy -> первый настоящий узел -> второй узел
```

Он нужен, когда голова результата может измениться или еще неизвестна. Благодаря `dummy` первый настоящий узел обрабатывается так же, как остальные: он всегда добавляется после некоторого предыдущего узла.

После завершения алгоритма результат находится в `dummy.next`.

Значение самого `dummy` обычно не используется.

## Пример 2. Слияние двух отсортированных списков {#primer-2-sliyanie-dvukh-otsortirovannykh-spiskov}

Даны:

```text
1 -> 4 -> 7
2 -> 3 -> 8
```

Нужно получить:

```text
1 -> 2 -> 3 -> 4 -> 7 -> 8
```

```python
def merge_sorted_lists(
    first: ListNode | None,
    second: ListNode | None,
) -> ListNode | None:
    dummy = ListNode(0)

    # Tail всегда указывает на последний узел результата.
    tail = dummy

    while first is not None and second is not None:
        if first.value <= second.value:
            # Присоединяем текущий узел первого списка.
            tail.next = first
            first = first.next
        else:
            # Присоединяем текущий узел второго списка.
            tail.next = second
            second = second.next

        # Передвигаем конец результата на присоединенный узел.
        tail = tail.next

    # Один список закончился. Оставшаяся часть другого
    # уже отсортирована, поэтому можно присоединить ее целиком.
    if first is not None:
        tail.next = first
    else:
        tail.next = second

    return dummy.next
```

Почему возвращается `dummy.next`, а не `dummy`? `dummy` — технический узел со значением `0`; он не является частью ответа.

Если длины списков равны `n` и `m`:

- время: `O(n + m)`;
- дополнительная память: `O(1)`, потому что используются существующие узлы.

## Медленный и быстрый указатели {#medlennyy-i-bystryy-ukazateli}

Это прием, при котором по одному списку одновременно идут два указателя:

- `slow` делает один шаг;
- `fast` делает два шага.

Пока быстрый указатель проходит весь список, медленный проходит примерно половину. Так можно найти середину без предварительного подсчета длины.

## Пример 3. Поиск середины {#primer-3-poisk-serediny}

```python
def find_middle(head: ListNode | None) -> ListNode | None:
    slow = head
    fast = head

    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next

    return slow
```

Для списка `10 -> 20 -> 30 -> 40 -> 50`:

| Шаг | `slow` | `fast` |
| --- | --- | --- |
| Начало | `10` | `10` |
| 1 | `20` | `30` |
| 2 | `30` | `50` |

После этого быстрый указатель не может сделать еще два шага. Медленный находится на `30`, то есть в середине.

Для списка четной длины функция вернет второй из двух средних узлов. Например, для `10 -> 20 -> 30 -> 40` результатом будет узел `30`.

- Время: `O(n)`.
- Память: `O(1)`.

## Зачем проверять fast и fast.next {#zachem-proveryat-fast-i-fast-next}

В строке `fast = fast.next.next` выполняются два перехода. Они безопасны, только если:

1. `fast` не равен `None`;
2. `fast.next` не равен `None`.

Поэтому условие цикла содержит обе проверки:

```python
while fast is not None and fast.next is not None:
```

Python вычисляет `and` слева направо. Если `fast is not None` ложно, правая часть не выполняется и обращения к `fast.next` не происходит.

## Что такое цикл в связном списке {#chto-takoe-tsikl-v-svyaznom-spiske}

В обычном списке последний узел ведет в `None`. В списке с циклом один из узлов ведет на уже встречавшийся узел:

```text
10 -> 20 -> 30 -> 40
      ^           |
      |___________|
```

Обычный обход `while current is not None` здесь никогда не закончится.

## Пример 4. Поиск цикла алгоритмом Флойда {#primer-4-poisk-tsikla-algoritmom-floyda}

```python
def has_cycle(head: ListNode | None) -> bool:
    slow = head
    fast = head

    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next

        if slow is fast:
            # Указатели встретились на одном объекте-узле.
            return True

    # Быстрый указатель дошел до конца, значит цикла нет.
    return False
```

Представь двух бегунов на круговой дорожке. Быстрый движется в два раза быстрее медленного. Если оба находятся внутри круга, быстрый со временем догонит медленного.

Если цикла нет, быстрый указатель доберется до `None`.

### Почему используется is, а не == {#pochemu-ispolzuetsya-is-a-ne}

Нужно проверить, что оба указателя ссылаются на **один и тот же узел**:

```python
if slow is fast:
```

Два разных узла могут хранить одинаковое значение. Сравнение только `slow.value == fast.value` ошибочно сообщило бы о встрече.

- Время: `O(n)`.
- Память: `O(1)`.

## Альтернативный поиск цикла через set {#alternativnyy-poisk-tsikla-cherez-set}

Можно сохранять посещенные узлы в множестве:

```python
def has_cycle_with_set(head: ListNode | None) -> bool:
    visited: set[ListNode] = set()
    current = head

    while current is not None:
        if current in visited:
            return True

        visited.add(current)
        current = current.next

    return False
```

Такой вариант проще придумать:

- время: `O(n)`;
- память: `O(n)`.

Алгоритм Флойда сложнее понять, но ему нужна только `O(1)` дополнительной памяти.

## Изменение головы списка {#izmenenie-golovy-spiska}

Операция может вернуть новую голову:

- разворот списка;
- удаление первого узла;
- добавление перед первым узлом;
- слияние списков.

Поэтому результат нужно присвоить:

```python
head = reverse_list(head)
```

Если просто вызвать `reverse_list(head)` и проигнорировать возвращаемое значение, переменная `head` продолжит ссылаться на старую голову. После разворота она стала последним узлом.

## Когда полезен dummy node {#kogda-polezen-dummy-node}

Используй фиктивный узел, если:

- результат строится с неизвестной головой;
- первый узел может быть удален;
- узлы добавляются в новый список по одному;
- хочется убрать отдельную обработку первого элемента.

Не нужно добавлять `dummy` в каждый алгоритм. Например, для поиска середины или цикла он ничего не упрощает.

## Частые ошибки {#chastye-oshibki}

1. Изменить `current.next` до сохранения следующего узла.
2. Забыть присвоить новую голову после разворота.
3. Обратиться к `fast.next`, когда `fast` равен `None`.
4. Вернуть `dummy`, а не `dummy.next`.
5. Не передвинуть `tail` после добавления узла.
6. Считать вставку `O(1)`, не учитывая поиск позиции.
7. Сравнивать значения вместо объектов при поиске цикла.
8. Использовать обычный бесконечный обход для списка с циклом.
9. Создавать новые узлы, когда задача требует переставить существующие ссылки.

1. Нарисуй три узла и подпиши все ссылки.

5. Реализуй слияние через `dummy` и `tail`.

7. Нарисуй цикл и проследи движение указателей Флойда.

## Задачи для самостоятельного решения {#zadachi-dlya-samostoyatelnogo-resheniya}

### Задача 1. Удаление N-го узла с конца {#zadacha-1-udalenie-n-go-uzla-s-kontsa}

Дан односвязный список и число `n`. Удали `n`-й узел с конца и верни голову списка.

Требования:

- пройти список за один основной проход;
- не преобразовывать список в массив;
- корректно обработать удаление первого узла.

Подсказка: поставь быстрый указатель на `n` шагов впереди медленного. Подумай, как `dummy` упростит удаление головы.

### Задача 2. Палиндром в связном списке {#zadacha-2-palindrom-v-svyaznom-spiske}

Определи, одинаково ли читаются значения списка слева направо и справа налево.

Например:

```text
1 -> 2 -> 2 -> 1  — палиндром
1 -> 2 -> 3       — не палиндром
```

Постарайся получить:

- время `O(n)`;
- дополнительную память `O(1)`.

Подумай, как объединить поиск середины и разворот второй половины. Дополнительно попробуй восстановить исходный список после проверки.
