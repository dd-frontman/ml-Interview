## Цель недели {#tsel-nedeli}

Научиться использовать стек для задач, где важен последний незавершенный элемент, а также освоить монотонный стек для поиска ближайшего большего или меньшего значения.

После недели нужно уметь:

- объяснить принцип LIFO;
- реализовать стек через `list`;
- безопасно работать с вершиной стека;
- проверять вложенные конструкции;
- вычислять выражения в обратной польской записи;
- определять направление монотонности;
- выбирать между хранением значений и индексов;
- объяснять сложность `O(n)` монотонного стека.

## Что такое стек {#chto-takoe-stek}

Стек работает по правилу LIFO:

```text
Last In, First Out
Последним пришел, первым вышел
```

Представь стопку тарелок. Новая тарелка кладется сверху. Забрать можно тоже только верхнюю.

Основные операции:

| Операция | Смысл | Python |
| --- | --- | --- |
| Push | Добавить элемент наверх | `stack.append(value)` |
| Pop | Удалить верхний элемент | `stack.pop()` |
| Peek | Посмотреть верхний элемент | `stack[-1]` |
| Empty | Проверить пустоту | `not stack` |

В Python стек обычно реализуется обычным списком:

```python
stack: list[int] = []

stack.append(10)  # Стек: [10].
stack.append(20)  # Стек: [10, 20], вершина равна 20.

top = stack[-1]  # Читаем 20, не удаляя его.
removed = stack.pop()  # Удаляем 20, стек снова [10].
```

`append()`, `pop()` с конца и `stack[-1]` выполняются за `O(1)` или амортизированно `O(1)`.

## Когда нужен стек {#kogda-nuzhen-stek}

Сильные сигналы:

- вложенные скобки или теги;
- команда отмены последнего действия;
- нужно вернуться к последнему незавершенному состоянию;
- выражение вычисляется в порядке, отличном от обычного чтения;
- рекурсию нужно заменить явной структурой;
- ищется ближайший больший или меньший элемент.

## Пример 1. Правильная скобочная последовательность {#primer-1-pravilnaya-skobochnaya-posledovatelnost}

Нужно проверить, что каждой закрывающей скобке соответствует последняя незакрытая скобка того же типа.

```python
def is_valid_parentheses(text: str) -> bool:
    opening_by_closing = {
        ")": "(",
        "]": "[",
        "}": "{",
    }
    stack: list[str] = []

    for character in text:
        if character not in opening_by_closing:
            # Открывающую скобку пока нельзя завершить,
            # поэтому сохраняем ее на вершине стека.
            stack.append(character)
            continue

        if not stack:
            # Закрывающая скобка есть, а открывающей перед ней нет.
            return False

        last_opening = stack.pop()

        if last_opening != opening_by_closing[character]:
            # Закрывается не последний открытый тип скобки.
            return False

    # Пустой стек означает, что все открытые скобки закрылись.
    return not stack
```

### Пошаговый разбор {#poshagovyy-razbor}

Для строки `"([])"`:

| Символ | Действие | Стек после действия |
| --- | --- | --- |
| `(` | Добавить | `['(']` |
| `[` | Добавить | `['(', '[']` |
| `]` | Удалить соответствующую `[` | `['(']` |
| `)` | Удалить соответствующую `(` | `[]` |

Каждый символ добавляется или удаляется не более одного раза.

- Время: `O(n)`.
- Память: `O(n)` в худшем случае.

## Почему недостаточно считать скобки {#pochemu-nedostatochno-schitat-skobki}

Для одного типа скобок можно увеличивать и уменьшать счетчик. Для нескольких типов этого мало.

Строки `"([)]"` содержат одинаковое количество открывающих и закрывающих скобок, но порядок неправильный. Стек сохраняет именно порядок вложенности.

## Пример 2. Обратная польская запись {#primer-2-obratnaya-polskaya-zapis}

В обратной польской записи оператор идет после двух операндов:

```text
["2", "3", "+", "4", "*"]
```

Это выражение означает `(2 + 3) * 4`.

```python
def evaluate_rpn(tokens: list[str]) -> int:
    operations = {"+", "-", "*", "/"}
    stack: list[int] = []

    for token in tokens:
        if token not in operations:
            # Число пока не имеет оператора, сохраняем его.
            stack.append(int(token))
            continue

        # Сначала извлекается правый операнд, потому что он лежит сверху.
        right = stack.pop()
        left = stack.pop()

        if token == "+":
            result = left + right
        elif token == "-":
            result = left - right
        elif token == "*":
            result = left * right
        else:
            # int обрезает результат к нулю, как требуется в этой задаче.
            result = int(left / right)

        # Результат становится операндом для следующей операции.
        stack.append(result)

    return stack[-1]
```

Важно не перепутать `left` и `right`: для сложения это незаметно, но `5 - 2` и `2 - 5` дают разные результаты.

## Что такое монотонный стек {#chto-takoe-monotonnyy-stek}

Монотонный стек хранит элементы в определенном порядке:

- возрастающем;
- убывающем.

Перед добавлением нового элемента из вершины удаляются элементы, нарушающие порядок.

Он нужен не ради сортировки. В стеке остаются только кандидаты, для которых будущий ответ еще не найден.

## Как выбрать направление {#kak-vybrat-napravlenie}

Если ищется следующий **больший** элемент, часто используется убывающий стек: сверху находятся элементы, ожидающие большего значения.

Если ищется следующий **меньший** элемент, часто используется возрастающий стек.

Вместо запоминания формулировки задай вопросы:

1. Для каких прошлых элементов новый элемент становится ответом?
2. При каком сравнении элемент нужно удалить из стека?
3. Нужен сам элемент или расстояние до него?

## Пример 3. Следующий более теплый день {#primer-3-sleduyushchiy-bolee-teplyy-den}

Для каждого дня нужно вернуть количество дней до более высокой температуры.

Нужно хранить индексы, потому что ответ является расстоянием между позициями.

```python
def daily_temperatures(temperatures: list[int]) -> list[int]:
    result = [0] * len(temperatures)
    stack: list[int] = []  # Индексы дней без найденного ответа.

    for current_index, current_temperature in enumerate(temperatures):
        while (
            stack
            and temperatures[stack[-1]] < current_temperature
        ):
            # Текущий день теплее дня на вершине стека.
            previous_index = stack.pop()

            # Разность индексов равна количеству дней ожидания.
            result[previous_index] = current_index - previous_index

        # Для текущего дня более теплый день пока неизвестен.
        stack.append(current_index)

    # Индексы, оставшиеся в стеке, не имеют более теплого дня.
    # В result для них уже записан 0.
    return result
```

### Пошаговый разбор {#poshagovyy-razbor-2}

Для `[73, 74, 75, 71, 72]`:

| Температура | Что удаляется | Стек индексов после шага | Изменение ответа |
| --- | --- | --- | --- |
| 73 | Ничего | `[0]` | Нет |
| 74 | Индекс 0 | `[1]` | `result[0] = 1` |
| 75 | Индекс 1 | `[2]` | `result[1] = 1` |
| 71 | Ничего | `[2, 3]` | Нет |
| 72 | Индекс 3 | `[2, 4]` | `result[3] = 1` |

Температуры по индексам в стеке идут невозрастающе. Индекс `2` остается, потому что после `75` более теплого дня нет.

## Почему сложность O(n), хотя есть while {#pochemu-slozhnost-o-n-khotya-est-while}

Каждый индекс:

- один раз добавляется через `append()`;
- не более одного раза удаляется через `pop()`.

Всего не более `2n` операций со стеком. Поэтому сложность `O(n)`, а не `O(n²)`.

## Пример 4. Следующий больший элемент {#primer-4-sleduyushchiy-bolshiy-element}

```python
def next_greater(numbers: list[int]) -> list[int]:
    result = [-1] * len(numbers)
    stack: list[int] = []

    for current_index, current_number in enumerate(numbers):
        while stack and numbers[stack[-1]] < current_number:
            previous_index = stack.pop()
            result[previous_index] = current_number

        stack.append(current_index)

    return result
```

Если нужен сам следующий больший элемент, в ответ записывается `current_number`. Если нужно расстояние, записывается разность индексов.

## Значения или индексы {#znacheniya-ili-indeksy}

Храни значения, если нужен только порядок или вычисление выражения.

Храни индексы, если нужно:

- расстояние;
- позиция ответа;
- обратиться к другим данным по той же позиции;
- различать одинаковые значения в разных местах.

## Частые ошибки {#chastye-oshibki}

1. Вызвать `pop()` или `stack[-1]` без проверки пустоты.
2. Перепутать правый и левый операнд.
3. Проверить только количество скобок, но не вложенность.
4. Хранить температуру, когда для ответа нужен индекс.
5. Выбрать неверное сравнение `<` или `<=` при дубликатах.
6. Считать вложенный `while` автоматически квадратичным.
7. Удалить из монотонного стека элемент до записи его ответа.

## Задачи для самостоятельного решения {#zadachi-dlya-samostoyatelnogo-resheniya}

### Задача 1. Стек с минимумом {#zadacha-1-stek-s-minimumom}

Реализуй `MinStack` с операциями:

- `push(value)`;
- `pop()`;
- `top()`;
- `get_min()`.

Все операции должны выполняться за `O(1)`. Нельзя каждый раз вызывать `min()` для всего стека.

Подсказка: вместе с обычным значением можно хранить минимум, актуальный на момент добавления.

### Задача 2. Максимальный прямоугольник гистограммы {#zadacha-2-maksimalnyy-pryamougolnik-gistogrammy}

Дан список высот столбцов шириной `1`. Найди максимальную площадь прямоугольника.

```text
[2, 1, 5, 6, 2, 3] -> 10
```

Подумай:

- когда высота на вершине перестает быть возможным продолжением;
- какой индекс считать началом прямоугольника после удаления;
- зачем после основного прохода обработать оставшиеся столбцы.
