## Цель недели {#tsel-nedeli}

Научиться распознавать задачи, в которых элементы нужно обрабатывать в порядке поступления, и использовать для этого `collections.deque`.

После недели нужно уметь:

- объяснить принцип FIFO;
- отличить очередь от стека;
- добавлять и удалять элементы с обоих концов `deque`;
- объяснить, почему `list.pop(0)` работает медленно;
- использовать очередь в BFS;
- обходить данные по уровням;
- применять монотонную очередь для максимума в скользящем окне;
- оценивать время и дополнительную память алгоритма.

## Что такое очередь {#chto-takoe-ochered}

Очередь работает по правилу FIFO:

```text
First In, First Out
Первым пришел, первым вышел
```

Представь очередь людей в кассу. Человек, который пришел первым, должен быть обслужен первым. Новые люди встают в конец очереди.

Основные операции:

| Операция | Смысл | Python с `deque` |
| --- | --- | --- |
| Enqueue | Добавить в конец | `queue.append(value)` |
| Dequeue | Удалить из начала | `queue.popleft()` |
| Front | Посмотреть первый элемент | `queue[0]` |
| Empty | Проверить пустоту | `not queue` |

## Почему используется deque {#pochemu-ispolzuetsya-deque}

В Python очередь обычно создается через `collections.deque`:

```python
from collections import deque


queue: deque[str] = deque()

queue.append("первая задача")
queue.append("вторая задача")

current_task = queue.popleft()  # Удаляется "первая задача".
next_task = queue[0]  # В начале осталась "вторая задача".
```

`deque` расшифровывается как **double-ended queue**, то есть двусторонняя очередь. Она умеет эффективно работать с обоими концами:

- `append(value)` — добавить справа;
- `pop()` — удалить справа;
- `appendleft(value)` — добавить слева;
- `popleft()` — удалить слева.

Все четыре операции выполняются за `O(1)`.

## Почему не подходит list.pop(0) {#pochemu-ne-podkhodit-list-pop-0}

Обычный список хранит элементы подряд. После удаления первого элемента оставшиеся элементы нужно сдвинуть на одну позицию влево.

```python
numbers = [10, 20, 30, 40]
numbers.pop(0)

# После удаления Python должен переместить 20, 30 и 40.
```

Одно удаление через `pop(0)` занимает `O(n)`. Если удалять так все элементы, суммарная сложность может стать `O(n²)`.

У `deque` элементы не требуется сдвигать, поэтому `popleft()` работает за `O(1)`.

## Когда нужна очередь {#kogda-nuzhna-ochered}

Сильные сигналы:

- элементы обрабатываются в порядке поступления;
- нужно сначала обработать ближайшие состояния;
- выполняется обход дерева по уровням;
- ищется кратчайший путь в невзвешенном графе;
- моделируется очередь задач, клиентов или событий;
- нужно хранить элементы текущего окна.

## Пример 1. Обработка задач по порядку {#primer-1-obrabotka-zadach-po-poryadku}

Пусть задачи поступают списком. Нужно вернуть их в том порядке, в котором обработает очередь.

```python
from collections import deque


def process_tasks(tasks: list[str]) -> list[str]:
    queue: deque[str] = deque(tasks)
    processed_tasks: list[str] = []

    while queue:
        # Берем самую старую задачу из начала очереди.
        current_task = queue.popleft()

        # Сохраняем ее как обработанную.
        processed_tasks.append(current_task)

    return processed_tasks
```

Здесь очередь не меняет порядок данных, но явно показывает правило обработки. Каждый элемент один раз добавлен и один раз удален.

- Время: `O(n)`.
- Дополнительная память: `O(n)`.

## Что такое BFS {#chto-takoe-bfs}

BFS означает **Breadth-First Search**, или поиск в ширину.

Алгоритм сначала посещает все вершины на расстоянии `1` от начала, затем на расстоянии `2`, потом на расстоянии `3` и так далее.

Именно очередь обеспечивает такой порядок:

1. Начальная вершина добавляется в очередь.
2. Из начала извлекается очередная вершина.
3. Ее непосещенные соседи добавляются в конец.
4. Процесс продолжается, пока очередь не опустеет.

## Почему BFS находит кратчайший путь {#pochemu-bfs-nakhodit-kratchayshiy-put}

Это верно для **невзвешенного графа**, где каждый переход имеет одинаковую стоимость.

BFS идет слоями:

```text
расстояние 0: начальная вершина
расстояние 1: ее соседи
расстояние 2: соседи соседей
```

Когда вершина встречается впервые, более короткого пути к ней уже быть не может: все меньшие расстояния были обработаны раньше.

Для графа с разными весами ребер обычного BFS недостаточно. Там понадобятся другие алгоритмы, например Дейкстра.

## Пример 2. Расстояния в невзвешенном графе {#primer-2-rasstoyaniya-v-nevzveshennom-grafe}

Граф хранится как словарь: ключ — вершина, значение — список ее соседей.

```python
from collections import deque


def find_distances(
    graph: dict[str, list[str]],
    start: str,
) -> dict[str, int]:
    # Расстояние до начальной вершины равно нулю.
    distances = {start: 0}

    # В очереди находятся найденные, но еще не обработанные вершины.
    queue: deque[str] = deque([start])

    while queue:
        current_vertex = queue.popleft()

        for neighbor in graph[current_vertex]:
            if neighbor in distances:
                # Вершина уже посещалась. Повторно добавлять ее нельзя.
                continue

            # Сосед находится на один переход дальше текущей вершины.
            distances[neighbor] = distances[current_vertex] + 1

            # Позже обработаем соседей найденной вершины.
            queue.append(neighbor)

    return distances
```

Рассмотрим граф:

```text
A -- B -- D
|    |
C -- E
```

И списки смежности:

```python
graph = {
    "A": ["B", "C"],
    "B": ["A", "D", "E"],
    "C": ["A", "E"],
    "D": ["B"],
    "E": ["B", "C"],
}
```

### Пошаговый разбор {#poshagovyy-razbor}

Стартуем из `A`:

| Шаг | Извлеченная вершина | Что добавили | Очередь | Расстояния |
| --- | --- | --- | --- | --- |
| 0 | — | `A` | `[A]` | `A: 0` |
| 1 | `A` | `B`, `C` | `[B, C]` | `B: 1`, `C: 1` |
| 2 | `B` | `D`, `E` | `[C, D, E]` | `D: 2`, `E: 2` |
| 3 | `C` | Ничего | `[D, E]` | Без изменений |
| 4 | `D` | Ничего | `[E]` | Без изменений |
| 5 | `E` | Ничего | `[]` | Без изменений |

Вершина помечается посещенной **до** добавления в очередь. Если сделать это только после извлечения, один и тот же сосед может попасть в очередь несколько раз.

Если `V` — количество вершин, а `E` — количество ребер:

- время: `O(V + E)`;
- память: `O(V)`.

## Пример 3. Обход дерева по уровням {#primer-3-obkhod-dereva-po-urovnyam}

В дереве очередь позволяет отделить один уровень от следующего.

```python
from collections import deque


def level_order(root: "TreeNode | None") -> list[list[int]]:
    if root is None:
        return []

    queue = deque([root])
    levels: list[list[int]] = []

    while queue:
        current_level: list[int] = []

        # Размер фиксируется до цикла. Это количество узлов
        # именно текущего уровня, а не всей будущей очереди.
        level_size = len(queue)

        for _ in range(level_size):
            node = queue.popleft()
            current_level.append(node.value)

            if node.left is not None:
                queue.append(node.left)

            if node.right is not None:
                queue.append(node.right)

        levels.append(current_level)

    return levels
```

Почему нельзя писать `for _ in range(len(queue))` и ожидать, что новые узлы тоже попадут в этот же цикл? Значение `range(...)` вычисляется один раз перед началом цикла. Это как раз полезно: дети остаются в очереди для следующего уровня.

Каждый узел добавляется и извлекается один раз:

- время: `O(n)`;
- память: `O(w)`, где `w` — максимальная ширина дерева.

## Очередь и множество visited {#ochered-i-mnozhestvo-visited}

В графе могут быть циклы:

```text
A -> B -> C -> A
```

Без множества посещенных вершин BFS будет снова добавлять `A`, `B` и `C` и не завершится.

Иногда отдельное множество не нужно. В примере с расстояниями словарь `distances` одновременно хранит ответ и показывает, была ли вершина посещена.

## Что такое монотонная очередь {#chto-takoe-monotonnaya-ochered}

Монотонная очередь хранит только полезных кандидатов в упорядоченном виде.

Для максимума в окне значения в `deque` идут по убыванию. Перед добавлением нового значения из конца удаляются все меньшие значения: они уже не смогут стать максимумом, пока новое значение находится в окне.

Обычно хранятся **индексы**, потому что нужно понимать:

- вышел ли элемент за левую границу окна;
- какое значение соответствует индексу;
- где находится текущий максимум.

## Пример 4. Максимум в скользящем окне {#primer-4-maksimum-v-skolzyashchem-okne}

Для каждого окна длины `window_size` нужно найти максимальный элемент.

```python
from collections import deque


def max_sliding_window(
    numbers: list[int],
    window_size: int,
) -> list[int]:
    if window_size <= 0 or window_size > len(numbers):
        return []

    result: list[int] = []

    # Храним индексы. Значения по этим индексам идут по убыванию.
    candidates: deque[int] = deque()

    for right, number in enumerate(numbers):
        left = right - window_size + 1

        # Удаляем индекс, который оказался левее текущего окна.
        if candidates and candidates[0] < left:
            candidates.popleft()

        # Все меньшие значения справа больше не нужны:
        # новый элемент появился позже и при этом имеет большее значение.
        while candidates and numbers[candidates[-1]] <= number:
            candidates.pop()

        candidates.append(right)

        if left >= 0:
            # В начале deque всегда находится максимум текущего окна.
            result.append(numbers[candidates[0]])

    return result
```

Для `numbers = [1, 3, -1, -3, 5]` и окна `3`:

| Окно | Индексы-кандидаты | Максимум |
| --- | --- | --- |
| `[1, 3, -1]` | `[1, 2]` | `3` |
| `[3, -1, -3]` | `[1, 2, 3]` | `3` |
| `[-1, -3, 5]` | `[4]` | `5` |

Каждый индекс добавляется один раз и удаляется не более одного раза. Поэтому:

- время: `O(n)`;
- память: `O(k)`, где `k` — размер окна.

## Обычная и монотонная очередь {#obychnaya-i-monotonnaya-ochered}

| Структура | Что хранит | Для чего нужна |
| --- | --- | --- |
| Обычная очередь | Все ожидающие элементы | FIFO, BFS, обработка событий |
| Монотонная очередь | Только полезных кандидатов | Максимум или минимум в окне |

Монотонная очередь не заменяет обычную. Это отдельный прием для определенного вида задач.

## Частые ошибки {#chastye-oshibki}

1. Использовать `list.pop(0)` в большом цикле.
2. Перепутать `pop()` и `popleft()`.
3. Не проверить очередь перед чтением `queue[0]`.
4. Помечать вершину посещенной слишком поздно.
5. Забыть `visited` в графе с циклом.
6. Применять BFS к графу с разными весами и ожидать кратчайший путь.
7. Хранить значения в монотонной очереди, когда нужно удалять устаревшие индексы.
8. Не удалять элементы, вышедшие за левую границу окна.

## Задачи для самостоятельного решения {#zadachi-dlya-samostoyatelnogo-resheniya}

### Задача 1. Очередь через два стека {#zadacha-1-ochered-cherez-dva-steka}

Реализуй класс `MyQueue` с методами:

- `push(value)`;
- `pop()`;
- `peek()`;
- `empty()`.

Использовать `deque` нельзя. Доступны только два списка как два стека и операции с их концом.

Подсказка: один стек принимает новые элементы, а второй выдает их в обратном порядке. Перекладывать элементы нужно не при каждом вызове.

### Задача 2. Кратчайший путь в лабиринте {#zadacha-2-kratchayshiy-put-v-labirinte}

Дана прямоугольная матрица:

- `0` — свободная клетка;
- `1` — стена.

Найди минимальное количество шагов от начальной клетки до конечной. Двигаться можно вверх, вниз, влево и вправо.

Подумай:

- что будет вершиной графа;
- как получать соседей клетки;
- когда отмечать клетку посещенной;
- что вернуть, если путь отсутствует.
