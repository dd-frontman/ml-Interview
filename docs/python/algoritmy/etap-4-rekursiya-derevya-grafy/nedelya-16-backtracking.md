## Цель недели {#tsel-nedeli}

Научиться перебирать варианты как дерево решений, сохранять текущее состояние и правильно откатывать выбор после исследования ветви.

После недели нужно уметь:

- определить состояние одной ветви;
- сформулировать доступные выборы;
- записать условие готового ответа;
- применять схему choose → explore → unchoose;
- добавлять копию изменяемого пути;
- избегать повторных вариантов;
- отсекать бесполезные ветви;
- оценивать экспоненциальную сложность через размер дерева решений.

## Что такое backtracking {#chto-takoe-backtracking}

Backtracking — это DFS по дереву возможных решений.

На каждом уровне алгоритм:

1. Выбирает один вариант.
2. Изменяет текущее состояние.
3. Рекурсивно исследует продолжение.
4. Отменяет изменение.
5. Пробует следующий вариант.

Краткая схема:

```text
choose -> explore -> unchoose
```

Backtracking не означает случайный перебор. Нужно явно описать:

- что является уровнем дерева;
- какие варианты доступны;
- какие варианты уже использованы;
- когда путь становится ответом;
- когда ветвь можно остановить раньше.

## Общий шаблон {#obshchiy-shablon}

```python
def backtrack(state) -> None:
    if решение_готово:
        result.append(копия_состояния)
        return

    for choice in доступные_варианты:
        применить(choice)
        backtrack(state)
        отменить(choice)
```

Фактическая реализация зависит от задачи, но три действия вокруг рекурсивного вызова повторяются постоянно.

## Дерево решений {#derevo-resheniy}

Для списка `[1, 2]` каждое число можно:

- взять;
- не брать.

```text
                 []
              /      \
          взять 1    не брать 1
           [1]           []
          /   \         /   \
       [1,2]  [1]     [2]   []
```

Листья дерева являются четырьмя подмножествами.

Количество вариантов часто экспоненциальное не из-за плохой реализации, а потому что сам ответ содержит экспоненциальное количество комбинаций.

## Пример 1. Все подмножества {#primer-1-vse-podmnozhestva}

Удобный вариант: добавлять текущее подмножество в ответ на каждом узле дерева, а затем пробовать новые элементы только справа от `start`.

```python
def subsets(numbers: list[int]) -> list[list[int]]:
    result: list[list[int]] = []
    current: list[int] = []

    def backtrack(start: int) -> None:
        # Любой текущий путь является корректным подмножеством.
        # Нужна копия, потому что current продолжит изменяться.
        result.append(current.copy())

        for index in range(start, len(numbers)):
            # Choose: добавляем выбранный элемент.
            current.append(numbers[index])

            # Explore: дальше можно брать только элементы правее.
            backtrack(index + 1)

            # Unchoose: возвращаем current к прежнему состоянию.
            current.pop()

    backtrack(0)
    return result
```

Для `[1, 2, 3]` будут получены:

```text
[]
[1]
[1, 2]
[1, 2, 3]
[1, 3]
[2]
[2, 3]
[3]
```

Порядок может отличаться, но набор подмножеств должен быть тем же.

## Зачем нужен start {#zachem-nuzhen-start}

Без `start` после выбора `2` алгоритм снова мог бы выбрать `1`. Тогда появились бы лишние порядки `[1, 2]` и `[2, 1]`, хотя это одно подмножество.

`start` фиксирует правило: каждый следующий элемент берется только правее предыдущего.

## Почему нужна копия current {#pochemu-nuzhna-kopiya-current}

Ошибочный код:

```python
result.append(current)
```

В `result` несколько раз попадет ссылка на один и тот же список. После всех `pop()` этот список станет пустым, и ответы окажутся неправильными.

Правильно:

```python
result.append(current.copy())
```

Каждый ответ получает отдельный список с текущими значениями.

## Сложность подмножеств {#slozhnost-podmnozhestv}

Для `n` элементов существует `2ⁿ` подмножеств. Копирование каждого пути может занимать до `O(n)`.

- время: `O(n * 2ⁿ)` с учетом формирования ответа;
- стек и текущий путь: `O(n)`;
- сам результат: `O(n * 2ⁿ)` в верхней оценке.

Нельзя обещать полиномиальное время, если требуется вернуть все подмножества.

## Пример 2. Перестановки {#primer-2-perestanovki}

В перестановке порядок важен. На каждом уровне выбирается любой еще не использованный элемент.

```python
def permutations(numbers: list[int]) -> list[list[int]]:
    result: list[list[int]] = []
    current: list[int] = []
    used = [False] * len(numbers)

    def backtrack() -> None:
        if len(current) == len(numbers):
            result.append(current.copy())
            return

        for index, number in enumerate(numbers):
            if used[index]:
                continue

            # Choose.
            used[index] = True
            current.append(number)

            # Explore.
            backtrack()

            # Unchoose. Откатываем оба изменения.
            current.pop()
            used[index] = False

    backtrack()
    return result
```

### Почему отмечается индекс, а не значение {#pochemu-otmechaetsya-indeks-a-ne-znachenie}

Если во входе могут встречаться одинаковые числа, два равных значения все равно находятся на разных позициях. Массив `used` привязан к конкретным элементам входа.

Для задачи с уникальными числами можно использовать множество значений. Индексы являются более общим вариантом.

### Дерево перестановок {#derevo-perestanovok}

Для `[1, 2, 3]`:

- на первом уровне `3` выбора;
- на втором `2` выбора;
- на третьем `1` выбор.

Количество листьев:

```text
3 * 2 * 1 = 3! = 6
```

С учетом копирования каждого ответа время составляет `O(n * n!)`.

## Подмножества и перестановки {#podmnozhestva-i-perestanovki}

| Свойство | Подмножества | Перестановки |
| --- | --- | --- |
| Важен порядок | Нет | Да |
| Следующие варианты | Только правее `start` | Любой неиспользованный |
| Число результатов | `2ⁿ` | `n!` |
| Состояние | `current`, `start` | `current`, `used` |

Перед написанием кода определи, считаются ли `[1, 2]` и `[2, 1]` разными ответами.

## Пример 3. Combination Sum {#primer-3-combination-sum}

Дан список уникальных положительных чисел и `target`. Одно число можно использовать несколько раз. Нужно вернуть комбинации с заданной суммой.

```python
def combination_sum(
    candidates: list[int],
    target: int,
) -> list[list[int]]:
    candidates.sort()
    result: list[list[int]] = []
    current: list[int] = []

    def backtrack(start: int, remaining: int) -> None:
        if remaining == 0:
            result.append(current.copy())
            return

        for index in range(start, len(candidates)):
            number = candidates[index]

            if number > remaining:
                # После сортировки все следующие числа еще больше.
                break

            current.append(number)

            # Передаем index, а не index + 1:
            # текущее число разрешено использовать повторно.
            backtrack(index, remaining - number)

            current.pop()

    backtrack(0, target)
    return result
```

### Почему используется remaining {#pochemu-ispolzuetsya-remaining}

Можно каждый раз вычислять `sum(current)`, но это дополнительный проход по пути. Переменная `remaining` обновляется за `O(1)` и сразу показывает:

- `remaining == 0` — ответ готов;
- `number > remaining` — число уже не подходит;
- положительный остаток — поиск продолжается.

### Зачем сортировка {#zachem-sortirovka}

После сортировки при `number > remaining` можно выполнить `break`, потому что все следующие числа не меньше текущего.

Это пример **pruning** — отсечения ветви, которая точно не приведет к ответу.

## Что такое pruning {#chto-takoe-pruning}

Pruning уменьшает количество исследуемых ветвей за счет проверки ограничений до рекурсивного вызова.

Примеры:

- текущая сумма уже больше `target`;
- закрывающих скобок стало больше открывающих;
- клетка занята;
- значение уже использовано на текущем уровне;
- оставшихся элементов недостаточно для завершения решения.

Pruning не должен удалять потенциально правильные ответы. Условие отсечения нужно уметь доказать.

## Пример 4. Генерация правильных скобок {#primer-4-generatsiya-pravilnykh-skobok}

Нужно построить все правильные последовательности из `pairs` пар.

Состояние:

- текущая строка;
- количество открывающих скобок;
- количество закрывающих скобок.

Правила:

- открывающую можно добавить, пока их меньше `pairs`;
- закрывающую можно добавить, только если открывающих уже больше;
- ответ готов, когда длина равна `2 * pairs`.

```python
def generate_parentheses(pairs: int) -> list[str]:
    result: list[str] = []
    current: list[str] = []

    def backtrack(opened: int, closed: int) -> None:
        if len(current) == 2 * pairs:
            result.append("".join(current))
            return

        if opened < pairs:
            current.append("(")
            backtrack(opened + 1, closed)
            current.pop()

        if closed < opened:
            current.append(")")
            backtrack(opened, closed + 1)
            current.pop()

    backtrack(0, 0)
    return result
```

Алгоритм вообще не создает строку, у которой в префиксе закрывающих скобок больше, чем открывающих. Неправильные ветви отсекаются до появления.

## Два способа строить состояние {#dva-sposoba-stroit-sostoyanie}

### Изменение одного списка {#izmenenie-odnogo-spiska}

```python
current.append(choice)
backtrack()
current.pop()
```

Преимущества:

- меньше промежуточных объектов;
- явно виден откат.

Недостаток: легко забыть `pop()`.

### Передача нового объекта {#peredacha-novogo-obekta}

```python
backtrack(current + [choice])
```

Преимущества:

- старое состояние не изменяется;
- откат не нужен.

Недостаток: на каждом вызове создается новый список и копируются элементы.

Для обучения полезно освоить первый вариант, потому что он показывает основную механику backtracking.

## Где должен находиться return {#gde-dolzhen-nakhoditsya-return}

После готового решения обычно нужен `return`:

```python
if решение_готово:
    result.append(current.copy())
    return
```

Без него функция может продолжить строить путь после полного ответа. Иногда это безопасно из-за других ограничений, но делает логику менее ясной и может породить лишние ветви.

## Дубликаты во входе {#dublikaty-vo-vkhode}

Если `numbers = [1, 2, 2]`, обычный алгоритм подмножеств создаст одинаковые варианты.

Типичная стратегия:

1. Отсортировать вход.
2. На одном уровне пропускать число, равное предыдущему.

```python
if index > start and numbers[index] == numbers[index - 1]:
    continue
```

Условие `index > start` важно. Оно запрещает повторный выбор одинакового значения только среди альтернатив одного уровня, но не запрещает использовать одинаковые значения из разных позиций в одном пути.

## Backtracking и обычный DFS {#backtracking-i-obychnyy-dfs}

Обычный DFS часто только посещает существующую структуру: дерево, граф или матрицу.

Backtracking строит дерево решений самостоятельно. Узел дерева — текущее частичное решение, а ребро — сделанный выбор.

Backtracking использует DFS, но дополнительно управляет изменяемым состоянием и откатом.

## Как оценивать сложность {#kak-otsenivat-slozhnost}

Для перебора удобно оценить:

1. Сколько вариантов есть на одном уровне.
2. Какова максимальная глубина.
3. Сколько листьев получится.
4. Сколько стоит сохранить один ответ.

Примеры:

| Задача | Число результатов | Примерная сложность |
| --- | --- | --- |
| Подмножества | `2ⁿ` | `O(n * 2ⁿ)` |
| Перестановки | `n!` | `O(n * n!)` |
| Бинарные строки длины `n` | `2ⁿ` | `O(n * 2ⁿ)` |

Pruning часто сильно ускоряет реальные входы, но худшая оценка может остаться экспоненциальной.

## Частые ошибки {#chastye-oshibki}

1. Забыть отменить выбор после рекурсивного вызова.
2. Выполнить `pop()` до рекурсивного вызова.
3. Добавить `current`, а не `current.copy()`.
4. Использовать один элемент повторно, когда это запрещено.
5. Запретить повторное использование, когда оно разрешено.
6. Генерировать перестановки вместо комбинаций.
7. Неверно определить условие готового ответа.
8. Не отсечь явно невозможную ветвь.
9. Удалить правильные варианты слишком агрессивным pruning.
10. Не обработать дубликаты во входе.

## План занятий {#plan-zanyatiy}

1. Нарисуй дерево выбора «взять или не взять» для трех чисел.
2. Реализуй подмножества через `start`.
3. Намеренно убери `.copy()` и проследи ошибку.
4. Реализуй перестановки через `used`.
5. Сравни комбинации и перестановки.
6. Реши Combination Sum с `remaining`.
7. Добавь pruning после сортировки.
8. Сгенерируй правильные скобки без неправильных префиксов.

## Задачи для самостоятельного решения {#zadachi-dlya-samostoyatelnogo-resheniya}

### Задача 1. Поиск слова в матрице {#zadacha-1-poisk-slova-v-matritse}

Дана матрица символов и слово. Определи, можно ли составить слово из соседних по вертикали или горизонтали клеток. Одну клетку нельзя использовать дважды в одном пути.

Подумай:

- что хранить как текущую позицию в слове;
- когда клетку помечать использованной;
- когда снимать эту отметку;
- какие проверки выполнить до рекурсивного вызова;
- почему `visited` относится к текущему пути, а не ко всему поиску.

### Задача 2. N Queens {#zadacha-2-n-queens}

Размести `n` ферзей на доске `n x n`, чтобы они не атаковали друг друга. Верни все допустимые расстановки.

Для быстрой проверки храни занятые:

- столбцы;
- диагонали `row - column`;
- диагонали `row + column`.

На каждом уровне выбирается позиция ферзя в одной строке. После возврата нужно удалить все три признака занятой позиции.
