## Цель недели {#tsel-nedeli}

Научиться видеть задачу как результат решения такой же, но меньшей задачи, и понимать, что происходит с каждым рекурсивным вызовом в памяти.

После недели нужно уметь:

- находить базовый случай;
- доказывать, что вход приближается к завершению;
- рисовать стек вызовов;
- понимать разницу между движением вглубь и возвратом результатов;
- оценивать время и память рекурсивного алгоритма;
- замечать повторяющиеся вычисления;
- добавлять мемоизацию;
- выбирать между рекурсией и итерацией.

## Что такое рекурсия {#chto-takoe-rekursiya}

Рекурсия — это способ решения задачи, при котором функция вызывает саму себя для более простого входа.

Например, факториал числа определяется так:

```text
5! = 5 * 4 * 3 * 2 * 1
5! = 5 * 4!
4! = 4 * 3!
```

Задача `factorial(5)` использует решение меньшей задачи `factorial(4)`.

У корректной рекурсии есть три части:

1. **Базовый случай** останавливает вызовы.
2. **Рекурсивный переход** уменьшает задачу.
3. **Возврат результата** собирает ответ из результатов меньших задач.

## Пример 1. Факториал {#primer-1-faktorial}

```python
def factorial(number: int) -> int:
    if number < 0:
        raise ValueError("Факториал определен только для number >= 0")

    if number <= 1:
        # 0! и 1! равны единице. Дальше вызывать функцию не нужно.
        return 1

    # Задача становится меньше: number уменьшается на единицу.
    return number * factorial(number - 1)
```

### Движение вниз по стеку {#dvizhenie-vniz-po-steku}

Для `factorial(4)` сначала создаются вызовы:

```text
factorial(4)
  ожидает factorial(3)
    ожидает factorial(2)
      ожидает factorial(1)
        возвращает 1
```

Пока `factorial(1)` не вернет результат, предыдущие вызовы не могут закончить умножение.

### Возврат результатов {#vozvrat-rezultatov}

После базового случая стек раскручивается в обратном порядке:

```text
factorial(1) -> 1
factorial(2) -> 2 * 1 = 2
factorial(3) -> 3 * 2 = 6
factorial(4) -> 4 * 6 = 24
```

Важно различать два процесса:

- при рекурсивных вызовах алгоритм движется к базовому случаю;
- при `return` результаты возвращаются от меньшей задачи к большей.

## Что хранится в стеке вызовов {#chto-khranitsya-v-steke-vyzovov}

Для каждого вызова Python хранит отдельный фрейм:

- аргументы;
- локальные переменные;
- место, куда нужно вернуться;
- промежуточное состояние вычисления.

У `factorial(4)` одновременно существуют фреймы для `4`, `3`, `2` и `1`. Поэтому рекурсивный алгоритм использует дополнительную память, даже если в коде нет списка или словаря.

Для факториала:

- время: `O(n)`;
- память стека: `O(n)`.

## Что произойдет без базового случая {#chto-proizoydet-bez-bazovogo-sluchaya}

```python
def broken_countdown(number: int) -> int:
    return broken_countdown(number - 1)
```

Функция продолжит создавать новые вызовы. Бесконечно это длиться не будет: Python остановит программу исключением `RecursionError`, когда будет превышен лимит глубины.

Базовый случай нужен не формально. Он определяет самый простой вход, ответ для которого уже известен.

## Вход должен приближаться к завершению {#vkhod-dolzhen-priblizhatsya-k-zaversheniyu}

Базового случая недостаточно, если рекурсивный переход до него не доходит:

```python
def broken_factorial(number: int) -> int:
    if number == 1:
        return 1

    return number * broken_factorial(number + 1)
```

При положительном `number` значение растет, поэтому функция удаляется от базового случая.

Перед запуском рекурсии ответь на вопрос: **какая величина уменьшается или становится ближе к условию остановки?**

## Пример 2. Сумма списка без срезов {#primer-2-summa-spiska-bez-srezov}

Можно суммировать элементы, передвигая индекс:

```python
def recursive_sum(numbers: list[int], index: int = 0) -> int:
    if index == len(numbers):
        # После последнего элемента добавлять больше нечего.
        return 0

    current_number = numbers[index]
    remaining_sum = recursive_sum(numbers, index + 1)

    return current_number + remaining_sum
```

Для `[4, 7, 2]` вычисление выглядит так:

```text
recursive_sum([4, 7, 2], 0)
= 4 + recursive_sum([4, 7, 2], 1)
= 4 + 7 + recursive_sum([4, 7, 2], 2)
= 4 + 7 + 2 + recursive_sum([4, 7, 2], 3)
= 4 + 7 + 2 + 0
= 13
```

### Почему не используется numbers[1:] {#pochemu-ne-ispolzuetsya-numbers-1}

Такой вариант выглядит короче:

```python
def recursive_sum_with_slices(numbers: list[int]) -> int:
    if not numbers:
        return 0

    return numbers[0] + recursive_sum_with_slices(numbers[1:])
```

Но `numbers[1:]` каждый раз создает новый список. Размеры копий будут `n - 1`, `n - 2`, `n - 3` и так далее.

Суммарно копируется порядка `n²` элементов:

- время может стать `O(n²)`;
- дополнительная память также заметно увеличивается.

Передача индекса сохраняет время `O(n)` и не создает копии списка.

## Потерянный return {#poteryannyy-return}

Частая ошибка:

```python
def countdown_result(number: int) -> int:
    if number == 0:
        return 0

    countdown_result(number - 1)
```

Самый глубокий вызов возвращает `0`, но предыдущий вызов не возвращает этот результат дальше. Функция завершится со значением `None`.

Если результат рекурсивного вызова является ответом текущего вызова, нужен `return`:

```python
def countdown_result(number: int) -> int:
    if number == 0:
        return 0

    return countdown_result(number - 1)
```

## Рекурсия до и после вызова {#rekursiya-do-i-posle-vyzova}

Положение действия относительно рекурсивного вызова меняет порядок обработки.

```python
def collect_forward(number: int) -> list[int]:
    if number == 0:
        return []

    result = collect_forward(number - 1)
    result.append(number)
    return result
```

Для `3` числа добавляются при возврате: `[1, 2, 3]`.

```python
def collect_backward(number: int) -> list[int]:
    if number == 0:
        return []

    return [number] + collect_backward(number - 1)
```

Для `3` число добавляется до углубления: `[3, 2, 1]`.

Эта идея станет особенно важна в обходах деревьев: обработка до, между или после рекурсивных вызовов дает разные виды DFS.

## Divide and Conquer {#divide-and-conquer}

**Divide and Conquer**, или «разделяй и властвуй», делит задачу на несколько независимых частей:

1. Разделить вход.
2. Рекурсивно решить части.
3. Объединить результаты.

Примеры:

- бинарный поиск оставляет половину массива;
- merge sort сортирует две половины;
- обход дерева решает задачу для левого и правого поддерева.

## Пример 3. Быстрое возведение в степень {#primer-3-bystroe-vozvedenie-v-stepen}

Обычное вычисление `base ** exponent` через последовательное умножение требует `exponent` шагов.

Можно использовать свойства:

```text
x^8 = x^4 * x^4
x^9 = x^4 * x^4 * x
```

```python
def fast_power(base: float, exponent: int) -> float:
    if exponent == 0:
        return 1.0

    if exponent < 0:
        return 1 / fast_power(base, -exponent)

    half = fast_power(base, exponent // 2)

    if exponent % 2 == 0:
        return half * half

    return half * half * base
```

Для `fast_power(2, 10)` показатели уменьшаются так:

```text
10 -> 5 -> 2 -> 1 -> 0
```

Глубина уменьшается в два раза на каждом шаге:

- время: `O(log n)`;
- память: `O(log n)`.

### Почему half вычисляется один раз {#pochemu-half-vychislyaetsya-odin-raz}

Ошибочный вариант:

```python
return fast_power(base, exponent // 2) * fast_power(base, exponent // 2)
```

Одинаковая подзадача запускается дважды. Каждый вызов снова порождает еще два вызова, и преимущество деления пополам теряется.

## Повторяющиеся подзадачи {#povtoryayushchiesya-podzadachi}

Классический пример — числа Фибоначчи:

```python
def fibonacci(number: int) -> int:
    if number <= 1:
        return number

    return fibonacci(number - 1) + fibonacci(number - 2)
```

Для `fibonacci(5)` вычисление `fibonacci(3)` выполняется несколько раз. Дерево вызовов быстро разрастается:

```text
fib(5)
├── fib(4)
│   ├── fib(3)
│   └── fib(2)
└── fib(3)
    ├── fib(2)
    └── fib(1)
```

Время наивной реализации экспоненциальное, приблизительно `O(2ⁿ)`.

## Пример 4. Мемоизация {#primer-4-memoizatsiya}

Мемоизация сохраняет ответ подзадачи и не вычисляет его повторно.

```python
def fibonacci_with_memo(
    number: int,
    memo: dict[int, int] | None = None,
) -> int:
    if memo is None:
        memo = {}

    if number <= 1:
        return number

    if number in memo:
        return memo[number]

    memo[number] = (
        fibonacci_with_memo(number - 1, memo)
        + fibonacci_with_memo(number - 2, memo)
    )

    return memo[number]
```

Теперь каждое значение от `0` до `number` вычисляется один раз:

- время: `O(n)`;
- словарь: `O(n)`;
- стек вызовов: `O(n)`.

Нельзя использовать `{}` как значение параметра по умолчанию. Один словарь сохранился бы между независимыми вызовами функции. Поэтому сначала используется `None`, а словарь создается внутри.

## Рекурсия и итерация {#rekursiya-i-iteratsiya}

Многие рекурсивные алгоритмы можно переписать через цикл и собственный стек.

| Рекурсия | Итерация |
| --- | --- |
| Часто ближе к определению задачи | Обычно лучше контролирует память |
| Использует стек вызовов Python | Использует явную структуру данных |
| Может достигнуть лимита глубины | Подходит для очень глубокого входа |
| Удобна для деревьев и backtracking | Удобна для линейных процессов |

Для простой суммы списка цикл понятнее и безопаснее. Для обхода дерева рекурсивное решение часто легче прочитать.

## Лимит рекурсии в Python {#limit-rekursii-v-python}

Python ограничивает глубину рекурсии. Это защищает процесс от переполнения системного стека.

Не следует автоматически увеличивать лимит через `sys.setrecursionlimit()`. Большое значение не делает алгоритм эффективнее и может привести к аварийному завершению процесса.

Если глубина может составлять десятки тысяч вызовов, лучше рассмотреть цикл или явный стек.

## Хвостовая рекурсия {#khvostovaya-rekursiya}

Хвостовой называется рекурсия, в которой рекурсивный вызов является последней операцией функции.

Некоторые языки умеют переиспользовать один фрейм для таких вызовов. Python не выполняет эту оптимизацию: каждый вызов все равно добавляется в стек.

Поэтому хвостовая рекурсия в Python не устраняет риск `RecursionError`.

## Как оценивать сложность рекурсии {#kak-otsenivat-slozhnost-rekursii}

Задай четыре вопроса:

1. Сколько рекурсивных вызовов порождает один вызов?
2. Насколько уменьшается вход?
3. Какая работа выполняется внутри одного вызова?
4. Какова максимальная глубина стека?

Примеры:

| Алгоритм | Вызовы | Время | Стек |
| --- | --- | --- | --- |
| Факториал | Один вызов для `n - 1` | `O(n)` | `O(n)` |
| Быстрая степень | Один вызов для `n / 2` | `O(log n)` | `O(log n)` |
| Наивный Fibonacci | Два повторяющихся вызова | `O(2ⁿ)` | `O(n)` |
| Fibonacci с memo | Каждое состояние один раз | `O(n)` | `O(n)` |

## Частые ошибки {#chastye-oshibki}

1. Не определить базовый случай.
2. Не приблизить аргумент к базовому случаю.
3. Забыть `return` перед рекурсивным вызовом.
4. Создавать срез списка на каждом уровне.
5. Не учитывать память стека.
6. Повторно вычислять одну подзадачу.
7. Вычислять одинаковый рекурсивный вызов дважды вместо сохранения результата.
8. Использовать изменяемый словарь как значение параметра по умолчанию.
9. Увеличивать лимит рекурсии вместо выбора итеративного алгоритма.

## Задачи для самостоятельного решения {#zadachi-dlya-samostoyatelnogo-resheniya}

### Задача 1. Рекурсивный бинарный поиск {#zadacha-1-rekursivnyy-binarnyy-poisk}

Реализуй поиск `target` в отсортированном списке. Функция должна вернуть индекс или `-1`.

Требования:

- не создавать срезы;
- передавать левую и правую границы;
- завершаться, когда диапазон стал пустым;
- работать за `O(log n)` времени и `O(log n)` памяти стека.

### Задача 2. Merge Sort {#zadacha-2-merge-sort}

Реализуй сортировку слиянием:

1. Раздели список на две половины.
2. Рекурсивно отсортируй половины.
3. Слей два отсортированных списка двумя указателями.

Объясни:

- почему глубина равна `O(log n)`;
- почему на каждом уровне обрабатывается `O(n)` элементов;
- откуда получается время `O(n log n)`;
- какая дополнительная память используется.
