## Greedy или Dynamic Programming {#greedy-ili-dynamic-programming}

Оба подхода принимают решения, но делают это по-разному.

**Greedy** выбирает лучший вариант прямо сейчас и больше не пересматривает выбор.

**Dynamic Programming** сравнивает результаты связанных подзадач и сохраняет вычисления.

Перед выбором спроси:

1. Можно ли доказать, что локально лучший выбор входит в глобально оптимальное решение?
2. Есть ли перекрывающиеся подзадачи?
3. Зависит ли ответ от нескольких предыдущих состояний?
4. Нужно ли рассмотреть несколько вариантов решения?

## Неделя 18. Greedy {#nedelya-18-greedy}

Жадный алгоритм не является догадкой. Для него нужно объяснить, почему принятый выбор не ухудшает оптимальный ответ.

### Что изучить {#chto-izuchit}

- локально и глобально оптимальный результат;
- greedy choice property;
- сортировку как подготовку к выбору;
- выбор по началу или концу интервала;
- поддержание текущей достижимой границы;
- контрпримеры для неверной стратегии;
- exchange argument на базовом уровне.

### Порядок решения {#poryadok-resheniya}

1. Сформулируй, какой локальный выбор кажется лучшим.
2. Попробуй построить контрпример.
3. Определи, какую информацию нужно хранить после выбора.
4. Объясни, почему возвращаться к предыдущему решению не нужно.
5. Только затем реализуй алгоритм.

### Практика {#praktika}

- `Maximum Subarray`;
- `Jump Game`;
- `Jump Game II`;
- `Gas Station`;
- `Partition Labels`;
- `Non-overlapping Intervals` как повторение.

### Частые ошибки {#chastye-oshibki}

- использовать greedy только потому, что решение выглядит коротким;
- не доказывать выбор;
- выбрать неверный критерий сортировки;
- перепутать текущий результат и лучший результат;
- не проверить отрицательные значения или недостижимое состояние.

## Неделя 19. Dynamic Programming I {#nedelya-19-dynamic-programming-i}

DP применяется, когда большая задача состоит из повторяющихся подзадач, а оптимальный ответ можно собрать из их результатов.

### Пять обязательных вопросов {#pyat-obyazatelnykh-voprosov}

Для каждой задачи явно запиши:

1. Что означает состояние `dp[i]`?
2. Из каких предыдущих состояний оно вычисляется?
3. Какие базовые случаи известны заранее?
4. В каком порядке вычисляются состояния?
5. Где находится итоговый ответ?

Если значение `dp[i]` невозможно объяснить одним предложением, состояние сформулировано недостаточно точно.

### Top-down {#top-down}

Рекурсивная функция решает нужные подзадачи и сохраняет результаты в словаре или через `functools.cache`.

Плюсы:

- близко к рекурсивной формулировке;
- вычисляются только нужные состояния.

Минусы:

- используется стек вызовов;
- можно упереться в ограничение рекурсии.

### Bottom-up {#bottom-up}

Таблица заполняется от базовых случаев к ответу.

Плюсы:

- нет рекурсивного стека;
- проще оптимизировать память.

Минус: нужно заранее определить правильный порядок заполнения.

### Практика {#praktika-2}

- `Climbing Stairs`;
- `Min Cost Climbing Stairs`;
- `House Robber`;
- `Coin Change`;
- `Decode Ways`.

Сначала напиши ручную мемоизацию через словарь. После понимания используй `functools.cache`.

## Неделя 20. Dynamic Programming II {#nedelya-20-dynamic-programming-ii}

Двумерное DP использует состояние с двумя параметрами, например `dp[row][column]` или `dp[left_index][right_index]`.

### Что изучить {#chto-izuchit-2}

- Grid DP;
- 0/1 Knapsack на уровне паттерна;
- выбор элемента или пропуск;
- Longest Common Subsequence;
- Longest Increasing Subsequence;
- восстановление выбранных элементов;
- замену таблицы одной или двумя строками;
- зависимость порядка обхода от перехода.

### Практика {#praktika-3}

- `Unique Paths`;
- `Minimum Path Sum`;
- `Longest Common Subsequence`;
- `Partition Equal Subset Sum`;
- `Longest Increasing Subsequence`.

### Оптимизация памяти {#optimizatsiya-pamyati}

Сначала напиши понятную полную таблицу. Оптимизируй память только после проверки перехода.

Если текущая строка зависит только от предыдущей, таблицу `rows * columns` можно заменить двумя строками. Иногда достаточно одной строки, но тогда порядок обновления становится частью корректности.

### Частые ошибки DP {#chastye-oshibki-dp}

- начать писать код без определения состояния;
- неверные базовые случаи;
- заполнение таблицы в неправильном порядке;
- путать невозможное состояние с нулевым ответом;
- возвращать не ту ячейку;
- оптимизировать память до получения правильного решения;
- запоминать формулу без понимания перехода.

## Неделя 21. Продвинутый трек {#nedelya-21-prodvinutyy-trek}

Эта неделя обязательна только для компаний с сильной алгоритмической секцией.

### Topological Sort {#topological-sort}

Используется для ориентированного ациклического графа и зависимостей. Изучи DFS-вариант и алгоритм Кана через входящие степени.

Примеры: порядок прохождения курсов, сборка зависимых задач.

### Union Find {#union-find}

Поддерживает объединение компонентов и проверку принадлежности к одной компоненте.

Изучи:

- массив `parent`;
- операцию `find`;
- операцию `union`;
- path compression;
- union by rank или size.

### Dijkstra {#dijkstra}

Находит кратчайшие пути в графе с неотрицательными весами. Для выбора ближайшей вершины используется priority queue.

Не применяй Dijkstra к отрицательным весам.

### Trie {#trie}

Префиксное дерево полезно для хранения строк, поиска слова и проверки префикса.

### Bit Manipulation {#bit-manipulation}

Изучи `&`, `|`, `^`, `~`, сдвиги и свойства XOR. Эта тема зависит от требований компании и встречается реже базовых паттернов.

Если продвинутые темы не нужны, потрать неделю на повторение Sliding Window, Binary Search, Trees, Graphs и базового DP.

## Разобранные примеры {#razobrannye-primery}

### Greedy: можно ли дойти до конца {#greedy-mozhno-li-doyti-do-kontsa}

Каждый элемент показывает максимальную длину прыжка из этой позиции.

```python
def can_reach_end(numbers: list[int]) -> bool:
    farthest = 0  # Самый дальний достижимый индекс.

    for index, jump in enumerate(numbers):
        if index > farthest:
            # Текущая позиция лежит за достижимой границей.
            return False

        # Из доступных вариантов сохраняем самый дальний результат.
        farthest = max(farthest, index + jump)

        if farthest >= len(numbers) - 1:
            # Последний индекс уже достижим, продолжать обход не нужно.
            return True

    return True
```

Жадный выбор здесь не фиксирует конкретный путь. Он сохраняет лучшую достижимую границу среди всех уже доступных позиций.

- Время: `O(n)`.
- Дополнительная память: `O(1)`.

### Одномерное DP: ограбление домов {#odnomernoe-dp-ograblenie-domov}

Нельзя брать деньги из двух соседних домов.

```python
def rob(houses: list[int]) -> int:
    previous_two = 0  # Лучший ответ до дома i - 2.
    previous_one = 0  # Лучший ответ до дома i - 1.

    for money in houses:
        # Есть два варианта:
        # 1. пропустить дом и оставить previous_one;
        # 2. взять дом и прибавить money к previous_two.
        current = max(previous_one, previous_two + money)

        # Сдвигаем состояния для следующего дома.
        previous_two = previous_one
        previous_one = current

    return previous_one
```

Состояние: `dp[i]` - максимальная сумма, которую можно получить из первых `i` домов.

Переход: `dp[i] = max(dp[i - 1], dp[i - 2] + houses[i])`.

Полная таблица не нужна, потому что переход использует только два предыдущих состояния.

### Двумерное DP: количество путей {#dvumernoe-dp-kolichestvo-putey}

Робот движется только вправо или вниз.

```python
def unique_paths(rows: int, columns: int) -> int:
    # В верхней строке до каждой клетки существует ровно один путь.
    paths = [1] * columns

    for _ in range(1, rows):
        for column in range(1, columns):
            # Текущее старое значение хранит число путей сверху.
            # Левое уже обновленное значение хранит число путей слева.
            paths[column] += paths[column - 1]

    return paths[-1]
```

- Время: `O(rows * columns)`.
- Память: `O(columns)` вместо полной таблицы `O(rows * columns)`.

## Итоговая проверка {#itogovaya-proverka}

Этап пройден, если ты можешь:

- объяснить, почему выбранный greedy-подход корректен;
- построить контрпример для неверной жадной стратегии;
- сформулировать состояние DP одним предложением;
- записать переход и базовые случаи до кода;
- реализовать top-down и bottom-up варианты;
- решить базовую задачу на одномерное и двумерное DP;
- оптимизировать память после правильной реализации;
- отличить DP от backtracking и greedy;
- определить, нужен ли продвинутый трек для выбранных компаний.

## Задачи для самостоятельного решения {#zadachi-dlya-samostoyatelnogo-resheniya}

### Задача 1. Минимальное количество монет {#zadacha-1-minimalnoe-kolichestvo-monet}

Даны номиналы монет и сумма `amount`. Найди минимальное количество монет, необходимое для получения суммы. Если это невозможно, верни `-1`.

Перед кодом запиши:

- значение `dp[current_amount]`;
- базовый случай;
- переход;
- значение для пока недостижимой суммы.

Проверь пример, на котором жадный выбор самой крупной монеты дает неправильный ответ.

### Задача 2. Разбиение строки {#zadacha-2-razbienie-stroki}

Дана строка и множество разрешенных слов. Определи, можно ли разбить строку на последовательность слов из множества.

```text
text = "applepenapple"
words = {"apple", "pen"}
result = True
```

Сформулируй одномерное состояние и объясни, какие предыдущие позиции нужно проверить.
