## Цель недели {#tsel-nedeli}

Научиться превращать рекурсивное описание с повторяющимися подзадачами в набор состояний, вычисляемых один раз.

После недели нужно уметь:

- распознавать перекрывающиеся подзадачи;
- формулировать значение `dp[i]` одним предложением;
- записывать переход до кода;
- выбирать базовые случаи;
- реализовывать top-down с мемоизацией;
- переводить решение в bottom-up;
- обозначать невозможное состояние;
- оптимизировать память до нескольких переменных;
- восстанавливать ход решения на маленьком примере.

## Что такое Dynamic Programming {#chto-takoe-dynamic-programming}

Dynamic Programming, или DP, решает большую задачу через результаты меньших подзадач и сохраняет эти результаты, чтобы не вычислять их повторно.

Два ключевых свойства:

1. **Перекрывающиеся подзадачи** — одинаковые состояния возникают несколько раз.
2. **Оптимальная подструктура** — лучший ответ большой задачи строится из лучших ответов меньших задач.

DP не является одной формулой. Это способ организовать вычисления.

## Пять вопросов перед кодом {#pyat-voprosov-pered-kodom}

Для каждой задачи запиши:

1. Что означает состояние?
2. Из каких состояний оно вычисляется?
3. Какие базовые случаи известны?
4. В каком порядке считать состояния?
5. Где находится итоговый ответ?

Например:

```text
dp[i] — количество способов подняться на ступень i
dp[i] = dp[i - 1] + dp[i - 2]
dp[0] = 1, dp[1] = 1
считаем слева направо
ответ находится в dp[steps]
```

Если `dp[i]` нельзя объяснить одним точным предложением, писать переход рано.

## Откуда появляется DP {#otkuda-poyavlyaetsya-dp}

Обычно путь выглядит так:

1. Написать рекурсивный выбор.
2. Увидеть повторяющиеся аргументы вызовов.
3. Сохранить ответы в memo.
4. Определить все состояния заранее.
5. Заполнить их снизу вверх.
6. При возможности сократить память.

Не обязательно всегда писать все версии, но этот порядок помогает понять переход.

## Пример 1. Climbing Stairs {#primer-1-climbing-stairs}

Можно подняться на `1` или `2` ступени. Нужно найти количество способов добраться до ступени `steps`.

Последнее действие:

- прийти со ступени `steps - 1` одним шагом;
- прийти со ступени `steps - 2` двойным шагом.

Эти варианты не пересекаются, поэтому количества складываются.

## Наивная рекурсия {#naivnaya-rekursiya}

```python
def climb_stairs_recursive(steps: int) -> int:
    if steps <= 1:
        return 1

    return (
        climb_stairs_recursive(steps - 1)
        + climb_stairs_recursive(steps - 2)
    )
```

Вызов для `steps - 2` возникает в нескольких ветвях. Получается экспоненциальное время, приблизительно `O(2ⁿ)`.

## Top-down с memo {#top-down-s-memo}

```python
def climb_stairs_top_down(steps: int) -> int:
    memo: dict[int, int] = {}

    def solve(current: int) -> int:
        if current <= 1:
            return 1

        if current in memo:
            return memo[current]

        memo[current] = solve(current - 1) + solve(current - 2)
        return memo[current]

    return solve(steps)
```

Каждое значение `current` вычисляется один раз:

- время: `O(n)`;
- memo: `O(n)`;
- стек: `O(n)`.

## Top-down через cache {#top-down-cherez-cache}

После понимания ручного memo можно использовать декоратор:

```python
from functools import cache


def climb_stairs_cached(steps: int) -> int:
    @cache
    def solve(current: int) -> int:
        if current <= 1:
            return 1

        return solve(current - 1) + solve(current - 2)

    return solve(steps)
```

Ключ кэша строится из аргументов функции. Они должны быть хешируемыми.

## Bottom-up {#bottom-up}

```python
def climb_stairs_bottom_up(steps: int) -> int:
    if steps <= 1:
        return 1

    dp = [0] * (steps + 1)
    dp[0] = 1
    dp[1] = 1

    for current in range(2, steps + 1):
        dp[current] = dp[current - 1] + dp[current - 2]

    return dp[steps]
```

Bottom-up начинает с известных базовых случаев. К моменту вычисления `dp[current]` обе зависимости уже заполнены.

## Оптимизация памяти {#optimizatsiya-pamyati}

Переход использует только два предыдущих значения. Весь список не нужен:

```python
def climb_stairs(steps: int) -> int:
    if steps <= 1:
        return 1

    previous_two = 1
    previous_one = 1

    for _ in range(2, steps + 1):
        current = previous_one + previous_two
        previous_two = previous_one
        previous_one = current

    return previous_one
```

- Время: `O(n)`.
- Память: `O(1)`.

Сначала полезно построить полную таблицу. Оптимизация до переменных выполняется после проверки перехода.

## Top-down и bottom-up {#top-down-i-bottom-up}

| Свойство | Top-down | Bottom-up |
| --- | --- | --- |
| Форма | Рекурсия + кэш | Цикл + таблица |
| Вычисляет | Только достигнутые состояния | Обычно все состояния |
| Стек вызовов | Есть | Нет |
| Порядок | Следует рекурсии | Нужно определить заранее |
| Оптимизация памяти | Не всегда очевидна | Часто проще |

Оба подхода могут иметь одинаковую асимптотику.

## Пример 2. House Robber {#primer-2-house-robber}

Нельзя выбирать два соседних дома. Нужно максимизировать сумму.

Определим:

```text
dp[i] — максимальная сумма из первых i домов
```

Для очередного дома есть два варианта:

1. Пропустить его: оставить `dp[i - 1]`.
2. Взять его: прибавить деньги к `dp[i - 2]`.

Переход:

```text
dp[i] = max(dp[i - 1], dp[i - 2] + current_money)
```

```python
def rob(houses: list[int]) -> int:
    previous_two = 0
    previous_one = 0

    for money in houses:
        skip_current = previous_one
        take_current = previous_two + money
        current = max(skip_current, take_current)

        previous_two = previous_one
        previous_one = current

    return previous_one
```

### Пошаговый разбор {#poshagovyy-razbor}

Для `[2, 7, 9, 3, 1]`:

| Дом | Пропустить | Взять | Лучший результат |
| --- | --- | --- | --- |
| `2` | `0` | `2` | `2` |
| `7` | `2` | `7` | `7` |
| `9` | `7` | `2 + 9 = 11` | `11` |
| `3` | `11` | `7 + 3 = 10` | `11` |
| `1` | `11` | `11 + 1 = 12` | `12` |

Жадный выбор самого дорогого доступного дома не всегда работает: выбор влияет на соседние возможности. DP сохраняет лучший результат обоих вариантов.

## Состояние по префиксу {#sostoyanie-po-prefiksu}

Во многих одномерных задачах `dp[i]` описывает ответ для префикса:

- первых `i` чисел;
- первых `i` символов;
- суммы `i`;
- позиции `i`.

Нужно четко различать:

- `i` как индекс элемента;
- `i` как количество обработанных элементов.

Если `dp[i]` означает первые `i` элементов, текущий элемент часто имеет индекс `i - 1`.

## Пример 3. Coin Change {#primer-3-coin-change}

Даны номиналы монет и сумма `amount`. Каждую монету можно использовать неограниченно. Нужно минимальное количество монет.

Состояние:

```text
dp[current] — минимум монет для суммы current
```

Базовый случай:

```text
dp[0] = 0
```

Остальные суммы пока недостижимы.

```python
def coin_change(coins: list[int], amount: int) -> int:
    impossible = amount + 1
    dp = [impossible] * (amount + 1)
    dp[0] = 0

    for current_amount in range(1, amount + 1):
        for coin in coins:
            previous_amount = current_amount - coin

            if previous_amount < 0:
                continue

            dp[current_amount] = min(
                dp[current_amount],
                dp[previous_amount] + 1,
            )

    if dp[amount] == impossible:
        return -1

    return dp[amount]
```

### Почему impossible равен amount + 1 {#pochemu-impossible-raven-amount-plus-1}

Если монета `1` существует, для суммы `amount` понадобится не более `amount` монет. Любое значение больше `amount` безопасно обозначает невозможность.

Можно использовать `float("inf")`, но целое значение иногда упрощает аннотации и сравнения.

### Почему невозможное состояние не равно нулю {#pochemu-nevozmozhnoe-sostoyanie-ne-ravno-nulyu}

Ноль означает реальный ответ только для суммы `0`. Если заполнить остальные ячейки нулями, `min()` будет выбирать их как лучший вариант.

Невозможность должна быть хуже любого допустимого ответа.

### Сложность {#slozhnost}

Если `c` — количество номиналов:

- время: `O(amount * c)`;
- память: `O(amount)`.

## Порядок вычисления {#poryadok-vychisleniya}

В Coin Change состояние `current_amount` зависит от меньшей суммы. Поэтому суммы считаются по возрастанию.

Если заполнить таблицу справа налево, нужное `dp[previous_amount]` может быть еще не вычислено.

Порядок обхода является частью алгоритма, а не оформлением кода.

## Пример 4. Decode Ways {#primer-4-decode-ways}

Строка цифр кодирует буквы:

```text
1 -> A
2 -> B
...
26 -> Z
```

Нужно посчитать количество расшифровок.

Состояние:

```text
dp[i] — количество способов расшифровать первые i символов
```

Последним фрагментом может быть:

- одна цифра от `1` до `9`;
- две цифры от `10` до `26`.

```python
def decode_ways(encoded: str) -> int:
    if not encoded:
        return 0

    dp = [0] * (len(encoded) + 1)
    dp[0] = 1
    dp[1] = 0 if encoded[0] == "0" else 1

    for length in range(2, len(encoded) + 1):
        one_digit = encoded[length - 1]
        two_digits = encoded[length - 2:length]

        if one_digit != "0":
            dp[length] += dp[length - 1]

        if "10" <= two_digits <= "26":
            dp[length] += dp[length - 2]

    return dp[-1]
```

### Зачем dp[0] = 1 {#zachem-dp-0-1}

Пустой префикс имеет один способ расшифровки: ничего не выбрать.

Это позволяет корректно добавить `dp[0]`, когда первые два символа образуют допустимый код.

Значение не означает, что пустая входная строка должна вернуть `1`: публичное поведение отдельно обрабатывается в начале функции.

## Пример 5. Min Cost Climbing Stairs {#primer-5-min-cost-climbing-stairs}

Можно начать перед ступенью `0` или `1`. После оплаты текущей ступени можно подняться на одну или две позиции.

Удобно определить:

```text
dp[i] — минимальная стоимость добраться до позиции i
```

Позиция `len(cost)` находится уже над лестницей.

```python
def min_cost_climbing_stairs(cost: list[int]) -> int:
    previous_two = 0
    previous_one = 0

    for position in range(2, len(cost) + 1):
        from_previous = previous_one + cost[position - 1]
        from_two_back = previous_two + cost[position - 2]
        current = min(from_previous, from_two_back)

        previous_two = previous_one
        previous_one = current

    return previous_one
```

Здесь индексы массива и позиции DP отличаются. Это нужно отдельно проверить на списке из двух элементов.

## Минимум, максимум или количество {#minimum-maksimum-ili-kolichestvo}

Переход зависит от вопроса:

- количество способов — складываем независимые варианты;
- минимальная стоимость — берем `min`;
- максимальная выгода — берем `max`;
- существование решения — используем логическое `or`.

Одинаковая структура состояний может решать разные задачи с разными операциями объединения.

## DP и greedy {#dp-i-greedy}

Greedy оставляет один локально лучший вариант и требует доказательства, что остальные не понадобятся.

DP сохраняет лучший ответ для каждого состояния и сравнивает несколько переходов.

В House Robber нельзя навсегда выбрать более дорогой из двух соседних домов: этот выбор влияет на следующий дом. Поэтому сравнение вариантов сохраняется в DP.

## DP и backtracking {#dp-i-backtracking}

Backtracking обычно строит все допустимые решения или ищет одно решение через перебор.

DP объединяет пути, которые привели в одинаковое состояние. Если дальнейший результат зависит только от состояния, историю пути хранить не нужно.

Например, для Coin Change неважно, в каком порядке была набрана сумма `current`; важен только минимальный результат для этой суммы.

## Как проверить переход вручную {#kak-proverit-perekhod-vruchnuyu}

1. Выбери вход из трех-пяти элементов.
2. Подпиши смысл каждой ячейки.
3. Заполни базовые случаи.
4. Для каждой новой ячейки выпиши все допустимые предыдущие состояния.
5. Сравни ручную таблицу с кодом.

Если таблицу нельзя заполнить вручную, переход еще не понятен.

## Частые ошибки {#chastye-oshibki}

1. Начать код без определения состояния.
2. Путать индекс и длину префикса.
3. Выбрать неправильный базовый случай.
4. Обозначить невозможность нулем.
5. Заполнять таблицу в неправильном порядке.
6. Вернуть последнюю вычисленную переменную вместо нужного состояния.
7. Не заметить повторяющиеся рекурсивные вызовы.
8. Оптимизировать память до проверки полной таблицы.
9. Использовать рекурсию без учета лимита глубины Python.
10. Запоминать формулу без объяснения смысла `dp[i]`.

## Задачи для самостоятельного решения {#zadachi-dlya-samostoyatelnogo-resheniya}

### Задача 1. Word Break {#zadacha-1-word-break}

Дана строка и множество слов. Определи, можно ли разбить всю строку на последовательность разрешенных слов.

Сформулируй:

```text
dp[i] — можно ли разбить первые i символов
```

Подумай:

- чему равен `dp[0]`;
- какие предыдущие позиции `start` нужно проверить;
- когда подстрока `text[start:i]` завершает корректное разбиение;
- как множество ускоряет проверку слова.

### Задача 2. Maximum Product Subarray {#zadacha-2-maximum-product-subarray}

Найди максимальное произведение непустого непрерывного подмассива.

Одного текущего максимума недостаточно: отрицательное минимальное произведение после умножения на отрицательное число может стать максимальным.

Храни два состояния:

- максимальное произведение с окончанием в текущей позиции;
- минимальное произведение с окончанием в текущей позиции.

Проверь решение на нулях и нескольких отрицательных числах.
