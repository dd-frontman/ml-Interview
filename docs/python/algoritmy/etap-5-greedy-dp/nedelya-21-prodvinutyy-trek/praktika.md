## Как выбрать инструмент {#kak-vybrat-instrument}

Сначала сформулируй, что именно меняется и какой ответ требуется:

| Сигнал в условии | Инструмент |
| --- | --- |
| Зависимости и порядок выполнения | Topological Sort |
| Динамическое объединение компонентов | Union Find |
| Неотрицательные веса и кратчайший путь | Dijkstra |
| Поиск по префиксу | Trie |
| Флаги, XOR, компактные подмножества | Bit Manipulation |

Не выбирай инструмент только по одному слову. Проверь ограничения:

- кратчайший путь без весов проще найти через BFS;
- проверка полного слова обычно решается через `set`;
- статические компоненты можно найти обычным DFS;
- отрицательные веса запрещают использование Дейкстры;
- битовая маска не уменьшает экспоненциальное количество подмножеств.

## План занятий {#plan-zanyatiy}

1. Повтори алгоритм Кана и входящие степени.
2. Реализуй Union Find без оптимизаций.
3. Добавь path compression и union by size.
4. Найди лишнее ребро через результат `union()`.
5. Проследи релаксацию Дейкстры на четырёх вершинах.
6. Добавь восстановление кратчайшего пути.
7. Реализуй `insert()`, `search()` и `starts_with()` для Trie.
8. Проверь свойства XOR на нескольких числах.
9. Сгенерируй подмножества битовыми масками.
10. Реши итоговые задачи без просмотра готовых реализаций.

## Частые ошибки {#chastye-oshibki}

### Topological Sort {#topological-sort}

1. Строить топологический порядок для неориентированного графа.
2. Не проверить, что обработаны все вершины.
3. Перепутать направление зависимости.

### Union Find {#union-find}

1. Выполнить `union()` для самих узлов вместо их корней.
2. Не применять path compression и union by size на больших входах.
3. Использовать структуру, когда нужно восстановить путь.

### Dijkstra {#dijkstra}

1. Применять алгоритм к отрицательным весам.
2. Не пропускать устаревшие записи в куче.
3. Считать BFS достаточным для разных весов.

### Trie {#trie}

1. Не хранить `is_word`.
2. Путать существование префикса и полного слова.
3. Использовать Trie вместо простого множества без необходимости.

### Битовые операции {#bitovye-operatsii}

1. Неверно понимать `~` для целых Python.
2. Путать логические и битовые операторы.
3. Применять заученный XOR-трюк при других ограничениях задачи.

## Задача 1. Accounts Merge {#zadacha-1-accounts-merge}

Каждый аккаунт содержит имя и список email. Аккаунты с общим email принадлежат одному человеку. Объедини связанные аккаунты.

Пример входных данных:

```python
accounts = [
    ["John", "john@mail.com", "john.work@mail.com"],
    ["John", "john.work@mail.com", "john.new@mail.com"],
    ["Mary", "mary@mail.com"],
]
```

Первый и второй аккаунты нужно объединить из-за общего адреса `john.work@mail.com`.

### Темы задачи {#temy-zadachi}

- Union Find;
- словари;
- группировка по корневому представителю;
- сортировка результата.

### Подсказки {#podskazki}

1. Реши, что будет элементом Union Find: индекс аккаунта или email.
2. Запоминай, где каждый email встретился впервые.
3. При повторной встрече объединяй текущий аккаунт с первым.
4. После всех объединений найди корень каждого email.
5. Сгруппируй адреса по корню и отсортируй их.

Полное решение не приведено: сначала реализуй задачу самостоятельно, используя страницу [Union Find](./union-find.md).

## Задача 2. Network Delay Time {#zadacha-2-network-delay-time}

Дан ориентированный граф времени передачи сигнала. Сигнал начинается в одной вершине. Найди время, за которое он достигнет всех вершин, или верни `-1`.

Пример:

```text
1 -> 2, вес 1
2 -> 3, вес 2
1 -> 3, вес 5
```

До вершины `3` выгоднее идти через `2`, поэтому задержка равна `3`, а не `5`.

### Темы задачи {#temy-zadachi-2}

- ориентированный взвешенный граф;
- Dijkstra;
- priority queue;
- максимальное значение среди кратчайших расстояний.

### Подсказки {#podskazki-2}

1. Построй список смежности с парами `(neighbor, weight)`.
2. Запусти Дейкстру из стартовой вершины.
3. Если хотя бы одна вершина осталась недостижимой, верни `-1`.
4. Иначе ответ равен максимуму среди кратчайших расстояний.
5. Не забывай пропускать устаревшие записи priority queue.

Полное решение не приведено: сначала адаптируй реализацию со страницы [Алгоритм Дейкстры](./dijkstra.md).
