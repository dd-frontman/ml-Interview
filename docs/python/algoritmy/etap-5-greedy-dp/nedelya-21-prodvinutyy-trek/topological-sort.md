## Какую проблему решаем {#kakuyu-problemu-reshaem}

Представь задачи, между которыми есть зависимости:

```text
установить зависимости -> собрать проект -> запустить тесты -> задеплоить
```

Нужно получить порядок, в котором каждая зависимость выполняется раньше зависящей от неё задачи. Это и делает **топологическая сортировка**.

Топологический порядок существует только для DAG:

```text
Directed Acyclic Graph
Ориентированный ациклический граф
```

Если зависимости образуют цикл, корректного порядка нет.

## Минимальный пример {#minimalnyy-primer}

Пусть задачи обозначены числами, а пара `(prerequisite, task)` означает, что `prerequisite` должна выполняться раньше `task`.

```python
dependencies = [
    (0, 1),
    (0, 2),
    (1, 3),
    (2, 3),
]
```

Один из допустимых порядков:

```text
0, 1, 2, 3
```

Порядок `0, 2, 1, 3` тоже правильный: задача `3` всё равно находится после `1` и `2`.

## Что такое `indegree` {#chto-takoe-indegree}

`indegree[vertex]` - количество рёбер, входящих в вершину.

Вершина с `indegree == 0` не зависит от необработанных вершин и может быть выполнена сейчас. После её обработки исходящие рёбра мысленно удаляются, поэтому входящие степени соседей уменьшаются.

Для примера выше:

```text
indegree[0] = 0
indegree[1] = 1
indegree[2] = 1
indegree[3] = 2
```

Сначала доступна только вершина `0`. После её обработки доступными становятся `1` и `2`.

## Алгоритм Кана {#algoritm-kana}

Алгоритм Кана использует очередь вершин с нулевой входящей степенью:

```python
from collections import deque


def build_order(
    tasks_count: int,
    dependencies: list[tuple[int, int]],
) -> list[int]:
    graph = [[] for _ in range(tasks_count)]
    indegree = [0] * tasks_count

    for prerequisite, task in dependencies:
        graph[prerequisite].append(task)
        indegree[task] += 1

    queue = deque(
        task
        for task, degree in enumerate(indegree)
        if degree == 0
    )
    order: list[int] = []

    while queue:
        task = queue.popleft()
        order.append(task)

        for dependent_task in graph[task]:
            indegree[dependent_task] -= 1

            if indegree[dependent_task] == 0:
                queue.append(dependent_task)

    if len(order) != tasks_count:
        # Необработанные вершины входят в цикл зависимостей.
        return []

    return order


dependencies = [(0, 1), (0, 2), (1, 3), (2, 3)]

print(build_order(4, dependencies))  # [0, 1, 2, 3]
```

## Разбор алгоритма по шагам {#razbor-algoritma-po-shagam}

1. Строим список смежности `graph`.
2. Подсчитываем входящие рёбра в `indegree`.
3. Добавляем в очередь все вершины с `indegree == 0`.
4. Извлекаем доступную вершину и добавляем её в ответ.
5. Уменьшаем входящую степень каждой зависимой задачи.
6. Если степень стала нулевой, задача готова к обработке.
7. В конце проверяем, удалось ли обработать все вершины.

## Почему длина показывает наличие цикла {#pochemu-dlina-pokazyvaet-nalichie-tsikla}

В цикле у каждой вершины остаётся хотя бы одно входящее ребро от другой вершины цикла. Ни одна из этих вершин не получит `indegree == 0` и не попадёт в очередь.

```text
0 -> 1 -> 2
     ^    |
     |____|
```

Если очередь опустела раньше, чем обработаны все вершины, оставшаяся часть графа содержит цикл.

```python
cyclic_dependencies = [(0, 1), (1, 2), (2, 1)]

print(build_order(3, cyclic_dependencies))  # []
```

## Сложность {#slozhnost}

- Время: `O(V + E)`.
- Память: `O(V + E)`.

Каждая вершина попадает в очередь не более одного раза, а каждое ребро обрабатывается один раз.

## Несколько правильных порядков {#neskolko-pravilnykh-poryadkov}

Если одновременно существует несколько вершин с `indegree == 0`, любую можно обработать первой. Поэтому у графа может быть несколько правильных топологических порядков.

Если требуется лексикографически минимальный порядок, вместо очереди используют min-heap. Тогда выбор следующей вершины занимает `O(log V)`.

## DFS-вариант {#dfs-variant}

В DFS вершина добавляется в ответ после всех зависимых вершин, а затем список разворачивается.

Нужны три состояния:

- `0` - вершина не посещена;
- `1` - вершина находится в текущем пути;
- `2` - вершина полностью обработана.

Ребро в вершину со статусом `1` означает цикл.

Алгоритм Кана обычно проще, когда условие говорит о входящих степенях, доступных задачах или уровнях. DFS удобен, когда решение уже построено вокруг рекурсивного обхода зависимостей.

## Типичные ошибки {#tipichnye-oshibki}

1. Применять топологическую сортировку к неориентированному графу.
2. Перепутать направление зависимости.
3. Не добавить изолированные вершины с `indegree == 0`.
4. Не проверить, что длина ответа равна количеству вершин.
5. Считать, что правильный порядок всегда единственный.

## Задачи для практики {#zadachi-dlya-praktiki}

1. Верни `True`, если все учебные курсы можно пройти с учётом зависимостей.
2. Построй один допустимый порядок букв по отсортированному словарю неизвестного языка.
3. Измени алгоритм Кана так, чтобы он возвращал лексикографически минимальный порядок.
