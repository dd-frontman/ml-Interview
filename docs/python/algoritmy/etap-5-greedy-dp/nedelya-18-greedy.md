## Цель недели {#tsel-nedeli}

Научиться распознавать задачи, в которых последовательность локально лучших решений приводит к глобально оптимальному ответу, и уметь объяснять корректность такого выбора.

После недели нужно уметь:

- отличать жадный алгоритм от перебора и DP;
- формулировать локальный выбор;
- искать контрпример для предполагаемой стратегии;
- использовать сортировку как подготовку;
- поддерживать достижимую границу;
- выбирать интервалы по правильному критерию;
- применять обменный аргумент на базовом уровне;
- объяснять, почему прошлое решение не нужно пересматривать.

## Что такое жадный алгоритм {#chto-takoe-zhadnyy-algoritm}

Жадный алгоритм на каждом шаге выбирает вариант, который выглядит лучшим прямо сейчас.

После выбора алгоритм обычно не возвращается назад и не сравнивает все возможные комбинации.

```text
сделать локально лучший выбор
обновить состояние
перейти к следующему шагу
```

Короткий цикл еще не делает алгоритм жадным. Главное свойство — принятое решение больше не пересматривается.

## Локальный и глобальный результат {#lokalnyy-i-globalnyy-rezultat}

**Локально оптимальный выбор** — лучший вариант на текущем шаге.

**Глобально оптимальный результат** — лучший итог для всей задачи.

Локальный выбор не всегда приводит к глобальному оптимуму.

Например, для монет `[1, 3, 4]` и суммы `6` выбор самой крупной доступной монеты даст:

```text
4 + 1 + 1 = 3 монеты
```

Но оптимальный ответ:

```text
3 + 3 = 2 монеты
```

Значит, стратегия «всегда брать крупнейшую монету» не является универсально правильной.

## Как проверять жадную идею {#kak-proveryat-zhadnuyu-ideyu}

Перед кодом пройди пять шагов:

1. Сформулируй локальный выбор одним предложением.
2. Определи, какое состояние остается после выбора.
3. Попробуй построить маленький контрпример.
4. Объясни, почему оптимальное решение можно заменить решением с твоим выбором.
5. Только после этого пиши код.

Если доказательства нет, возможно, требуется DP или другой перебор состояний.

## Обменный аргумент {#obmennyy-argument}

Один из способов доказать greedy — показать, что любое оптимальное решение можно преобразовать так, чтобы оно начиналось с жадного выбора, и результат не ухудшился.

Общая идея:

1. Возьмем некоторое оптимальное решение.
2. Если оно уже использует жадный выбор, все хорошо.
3. Иначе заменим его первый выбор на жадный.
4. Докажем, что после замены решение остается допустимым и не становится хуже.

Такой аргумент часто применяется к интервалам.

## Сортировка как подготовка {#sortirovka-kak-podgotovka}

Жадному алгоритму нередко нужен правильный порядок обработки:

- по времени окончания;
- по началу;
- по стоимости;
- по убыванию выгоды;
- по левой или правой границе.

Сортировка обычно занимает `O(n log n)`, а последующий проход — `O(n)`. Общая сложность остается `O(n log n)`.

Самая важная часть — выбрать правильный ключ сортировки.

## Пример 1. Максимальное число непересекающихся интервалов {#primer-1-maksimalnoe-chislo-neperesekayushchikhsya-intervalov}

Нужно выбрать как можно больше интервалов без пересечений.

Жадный выбор: каждый раз брать интервал с самым ранним окончанием.

Почему не самое раннее начало? Длинный интервал, начавшийся раньше, может занять место нескольких коротких.

```python
def select_non_overlapping(
    intervals: list[tuple[int, int]],
) -> list[tuple[int, int]]:
    if not intervals:
        return []

    # Раннее окончание оставляет максимум места будущим интервалам.
    sorted_intervals = sorted(intervals, key=lambda interval: interval[1])

    selected: list[tuple[int, int]] = []
    last_end = float("-inf")

    for start, end in sorted_intervals:
        if start < last_end:
            # Интервал пересекается с последним выбранным.
            continue

        selected.append((start, end))
        last_end = end

    return selected
```

### Почему раннее окончание правильно {#pochemu-rannee-okonchanie-pravilno}

Пусть оптимальное решение начинает с интервала, который заканчивается позже жадного.

Заменим его на интервал с самым ранним окончанием:

- новый интервал заканчивается не позже;
- все последующие интервалы оптимального решения остаются допустимыми;
- количество выбранных интервалов не уменьшается.

Значит, существует оптимальное решение, начинающееся с жадного выбора.

- Время: `O(n log n)` из-за сортировки.
- Дополнительная память: зависит от реализации сортировки и списка ответа.

## Удаление пересекающихся интервалов {#udalenie-peresekayushchikhsya-intervalov}

Если нужно удалить минимум интервалов, это та же задача в другой формулировке:

```text
минимум удалений = всего интервалов - максимум сохраненных
```

Можно считать удаления напрямую:

```python
def erase_overlap_intervals(
    intervals: list[tuple[int, int]],
) -> int:
    intervals.sort(key=lambda interval: interval[1])
    removals = 0
    last_end = float("-inf")

    for start, end in intervals:
        if start < last_end:
            removals += 1
            continue

        last_end = end

    return removals
```

Функция изменяет порядок исходного списка через `.sort()`. Если это запрещено, используй `sorted()`.

## Пример 2. Jump Game {#primer-2-jump-game}

Каждый элемент показывает максимальную длину прыжка из этой позиции. Нужно определить, достижим ли последний индекс.

Не требуется выбирать конкретный маршрут. Достаточно хранить самую дальнюю достижимую позицию.

```python
def can_reach_end(numbers: list[int]) -> bool:
    farthest = 0

    for index, max_jump in enumerate(numbers):
        if index > farthest:
            # До текущей позиции невозможно было добраться.
            return False

        # Среди всех доступных позиций сохраняем лучшую границу.
        farthest = max(farthest, index + max_jump)

        if farthest >= len(numbers) - 1:
            return True

    return True
```

### Инвариант {#invariant}

После обработки индексов от `0` до `index` переменная `farthest` хранит самый дальний индекс, достижимый из любой уже доступной позиции.

Если `index > farthest`, текущая позиция недостижима, а значит и все дальнейшие позиции нельзя использовать как точки прыжка.

- Время: `O(n)`.
- Память: `O(1)`.

## Почему не нужно моделировать каждый прыжок {#pochemu-ne-nuzhno-modelirovat-kazhdyy-pryzhok}

Из одной позиции может быть много вариантов. Полный перебор построил бы большое дерево путей.

Но для будущего важно только, насколько далеко можно добраться. Конкретная последовательность предыдущих прыжков не влияет на дальнейшие возможности.

Жадное состояние сжимает все рассмотренные пути в одну границу `farthest`.

## Пример 3. Максимальная сумма подмассива {#primer-3-maksimalnaya-summa-podmassiva}

Алгоритм Кадане решает задачу за один проход.

В каждой позиции выбирается:

- продолжить предыдущий подмассив;
- начать новый подмассив с текущего числа.

```python
def max_subarray_sum(numbers: list[int]) -> int:
    if not numbers:
        raise ValueError("Список не должен быть пустым")

    current_sum = numbers[0]
    best_sum = numbers[0]

    for number in numbers[1:]:
        # Если предыдущая сумма мешает, начинаем новый подмассив.
        current_sum = max(number, current_sum + number)

        # Отдельно сохраняем лучший результат за весь проход.
        best_sum = max(best_sum, current_sum)

    return best_sum
```

Для `[-2, 1, -3, 4, -1, 2, 1, -5]`:

| Число | Лучшая сумма с окончанием здесь | Общий максимум |
| --- | --- | --- |
| `-2` | `-2` | `-2` |
| `1` | `1` | `1` |
| `-3` | `-2` | `1` |
| `4` | `4` | `4` |
| `-1` | `3` | `4` |
| `2` | `5` | `5` |
| `1` | `6` | `6` |
| `-5` | `1` | `6` |

Ответ дает подмассив `[4, -1, 2, 1]`.

### Почему нельзя инициализировать нулем {#pochemu-nelzya-initsializirovat-nulem}

Если все числа отрицательные, ответом должен быть наибольший отрицательный элемент, а не пустой подмассив с суммой `0`.

Поэтому оба состояния начинаются с `numbers[0]`.

Алгоритм Кадане можно описывать как greedy или оптимизированное одномерное DP. Важнее четко определить состояние: лучший результат подмассива, который обязан закончиться в текущей позиции.

## Текущий и глобальный результат {#tekushchiy-i-globalnyy-rezultat}

Во многих greedy-задачах нужны две переменные:

- текущее состояние для продолжения;
- лучший результат среди всех прошлых состояний.

В Kadane:

- `current_sum` обязан заканчиваться на текущем числе;
- `best_sum` может закончиться где угодно раньше.

Если вернуть `current_sum`, результат будет неправильным, когда лучший подмассив закончился до конца списка.

## Пример 4. Partition Labels {#primer-4-partition-labels}

Нужно разделить строку на максимальное количество частей так, чтобы каждая буква встречалась только в одной части.

Сначала запоминается последняя позиция каждого символа.

```python
def partition_labels(text: str) -> list[int]:
    last_position = {
        character: index
        for index, character in enumerate(text)
    }

    result: list[int] = []
    partition_start = 0
    partition_end = 0

    for index, character in enumerate(text):
        # Текущая часть обязана включать последнее появление
        # каждой встреченной в ней буквы.
        partition_end = max(
            partition_end,
            last_position[character],
        )

        if index == partition_end:
            result.append(partition_end - partition_start + 1)
            partition_start = index + 1

    return result
```

### Инвариант границы {#invariant-granitsy}

`partition_end` — самая правая последняя позиция всех символов текущей части.

Пока `index < partition_end`, закончить часть нельзя: какой-то уже встреченный символ появится позже.

Когда `index == partition_end`, все символы части завершились. Закрытие в самый ранний допустимый момент максимизирует количество частей.

- Время: `O(n)`.
- Память: `O(k)`, где `k` — число различных символов.

## Пример 5. Лучшее время покупки акции {#primer-5-luchshee-vremya-pokupki-aktsii}

Разрешена одна покупка и одна последующая продажа.

```python
def max_profit(prices: list[int]) -> int:
    min_price = float("inf")
    best_profit = 0

    for price in prices:
        # Лучшая покупка к текущему дню — минимальная прошлая цена.
        min_price = min(min_price, price)

        # Продажа выполняется не раньше покупки,
        # потому что min_price обновляется только по пройденным дням.
        best_profit = max(best_profit, price - min_price)

    return best_profit
```

Состояние `min_price` заменяет проверку всех пар дней.

- Время: `O(n)` вместо `O(n²)`.
- Память: `O(1)`.

## Когда greedy не подходит {#kogda-greedy-ne-podkhodit}

Сигналы риска:

- локальный выбор влияет на много будущих ограничений;
- правильный результат требует сравнить несколько прошлых вариантов;
- легко построить контрпример;
- одна и та же подзадача повторяется;
- состояние определяется несколькими параметрами;
- после выбора может понадобиться вернуться назад.

В таких задачах проверь DP, backtracking или графовый алгоритм.

## Greedy, DP и backtracking {#greedy-dp-i-backtracking}

| Подход | Что делает |
| --- | --- |
| Greedy | Делает один выбор и не пересматривает его |
| DP | Сохраняет лучшие ответы для состояний и сравнивает варианты |
| Backtracking | Перебирает варианты и откатывает выбор |

Одна задача иногда имеет несколько решений. Например, Jump Game можно решить через DP, но greedy использует меньше памяти и проще после доказательства инварианта.

## Как строить контрпример {#kak-stroit-kontrprimer}

Начни с маленьких входов:

1. Два или три варианта выбора.
2. Один привлекательный локальный вариант.
3. Несколько менее привлекательных вариантов, которые вместе лучше.
4. Граничное значение: одинаковые концы, нули, отрицательные числа.

Для стратегии «брать самый короткий интервал» контрпримером может стать короткий интервал в середине, который пересекает два совместимых интервала по краям.

## Частые ошибки {#chastye-oshibki}

1. Использовать greedy без доказательства или инварианта.
2. Не искать контрпример.
3. Сортировать интервалы по началу вместо окончания.
4. Считать любой короткий цикл жадным алгоритмом.
5. Перепутать текущий и глобальный максимум.
6. Инициализировать Kadane нулем при отрицательных значениях.
7. Моделировать конкретный путь, когда достаточно границы достижимости.
8. Изменить вход через `.sort()`, когда это запрещено.
9. Не учесть пустой или недостижимый вход.

## План занятий {#plan-zanyatiy}

1. Сформулируй локальный и глобальный оптимум своими словами.
2. Построй контрпример для жадного выбора монет.
3. Реши выбор интервалов по раннему окончанию.
4. Докажи выбор через обменный аргумент.
5. Реализуй Jump Game через границу достижимости.
6. Проследи Kadane на отрицательном массиве.
7. Разбери расширение границы в Partition Labels.
8. Для каждой задачи запиши, почему выбор не пересматривается.

## Задачи для самостоятельного решения {#zadachi-dlya-samostoyatelnogo-resheniya}

### Задача 1. Jump Game II {#zadacha-1-jump-game-ii}

Каждый элемент задает максимальную длину прыжка. Гарантируется, что последний индекс достижим. Найди минимальное количество прыжков.

Попробуй обрабатывать позиции слоями:

- `current_end` — граница позиций, достижимых текущим числом прыжков;
- `farthest` — граница следующего слоя;
- когда индекс достигает `current_end`, требуется новый прыжок.

Объясни, чем этот процесс похож на BFS без явной очереди.

### Задача 2. Gas Station {#zadacha-2-gas-station}

Есть кольцевой маршрут. В точке `i` доступно `gas[i]` топлива, а переход к следующей точке требует `cost[i]`.

Найди стартовый индекс, позволяющий проехать круг, или верни `-1`.

Перед кодом докажи два утверждения:

1. Если общего топлива меньше общей стоимости, решения нет.
2. Если запас стал отрицательным на участке от старта до `i`, ни одна точка внутри этого участка не может быть подходящим стартом.
