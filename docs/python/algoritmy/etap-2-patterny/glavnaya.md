## Как распознавать паттерн {#kak-raspoznavat-pattern}

| Сигнал в условии | Возможный подход |
| --- | --- |
| Отсортированный массив, пара элементов | Two Pointers |
| Непрерывная подстрока или подмассив | Sliding Window |
| Много запросов суммы диапазона | Prefix Sum |
| Первый или последний подходящий элемент | Binary Search |
| Минимально допустимое значение | Binary Search on Answer |
| Пересекающиеся диапазоны времени | Sorting и Intervals |

Это подсказки, а не строгие правила. Сначала сформулируй brute-force решение и найди повторяющуюся работу.

## Неделя 4. Two Pointers {#nedelya-4-two-pointers}

### Что изучить {#chto-izuchit}

- указатели навстречу друг другу;
- два указателя, движущиеся в одном направлении;
- медленный и быстрый указатели;
- удаление дубликатов на месте;
- поиск пары в отсортированном массиве;
- сохранение инварианта между указателями.

Пример инварианта: все элементы левее `write_index` уже обработаны и находятся на правильных местах.

### Когда применять {#kogda-primenyat}

- массив отсортирован;
- сравниваются элементы с разных концов;
- нужно сжать массив на месте;
- каждый указатель движется только вперед;
- полный перебор пар дает `O(n²)`.

### Практика {#praktika}

- `Valid Palindrome`;
- `Two Sum II`;
- `Remove Duplicates from Sorted Array`;
- `Container With Most Water`;
- `3Sum`.

### Частые ошибки {#chastye-oshibki}

- не сдвинуть указатель в одной из веток;
- пропустить повторяющиеся значения;
- потерять ответ после изменения массива;
- применить два указателя к неотсортированным данным без обоснования.

## Неделя 5. Sliding Window {#nedelya-5-sliding-window}

Окно представляет непрерывный диапазон `[left, right]`.

### Фиксированное окно {#fiksirovannoe-okno}

Размер окна заранее известен. При сдвиге:

1. Добавь новый правый элемент.
2. Удали старый левый элемент.
3. Обнови ответ.

Так сумма каждого окна вычисляется за `O(1)`, а не пересчитывается полностью.

### Динамическое окно {#dinamicheskoe-okno}

Правая граница расширяет окно. Левая граница сдвигается, пока ограничение нарушено.

Важно сформулировать:

- что хранится в состоянии окна;
- когда окно считается допустимым;
- когда обновляется ответ;
- почему каждая граница проходит массив не более одного раза.

### Практика {#praktika-2}

- `Maximum Average Subarray I`;
- `Best Time to Buy and Sell Stock`;
- `Longest Substring Without Repeating Characters`;
- `Permutation in String`;
- `Minimum Size Subarray Sum`.

### Частые ошибки {#chastye-oshibki-2}

- использовать окно для непрерывности, которой нет в условии;
- обновлять ответ до восстановления ограничения;
- неправильно уменьшать частоту элемента;
- считать вложенный `while` квадратичным, хотя левая граница движется только вперед.

## Неделя 6. Prefix Sum {#nedelya-6-prefix-sum}

Префиксная сумма хранит результат для начала массива:

```text
prefix[i] = сумма первых i элементов
```

Тогда сумма диапазона `[left, right]` вычисляется как:

```text
prefix[right + 1] - prefix[left]
```

### Что изучить {#chto-izuchit-2}

- построение массива префиксов;
- запрос суммы диапазона за `O(1)`;
- начальный ноль в `prefix`;
- Prefix Sum вместе с Hash Map;
- prefix/suffix products;
- difference array как дополнительную тему.

### Практика {#praktika-3}

- `Running Sum of 1d Array`;
- `Find Pivot Index`;
- `Range Sum Query`;
- `Product of Array Except Self`;
- `Subarray Sum Equals K`.

### Частые ошибки {#chastye-oshibki-3}

- перепутать индекс исходного массива и префикса;
- получить ошибку на левой границе;
- пытаться применять обычное Sliding Window при отрицательных числах, когда условие окна перестает быть монотонным.

## Неделя 7. Binary Search {#nedelya-7-binary-search}

Бинарный поиск применим, когда пространство поиска упорядочено или ответ меняется монотонно.

### Что изучить {#chto-izuchit-3}

- закрытые и полуоткрытые границы;
- условие продолжения цикла;
- вычисление середины;
- поиск точного значения;
- поиск первой и последней подходящей позиции;
- lower bound и upper bound;
- поиск в повернутом массиве;
- Binary Search on Answer.

Сначала реализуй варианты вручную. После этого используй `bisect_left()` и `bisect_right()`.

### Практика {#praktika-4}

- `Binary Search`;
- `Search Insert Position`;
- `First Bad Version`;
- `Search in Rotated Sorted Array`;
- `Find Minimum in Rotated Sorted Array`;
- `Koko Eating Bananas`.

### Частые ошибки {#chastye-oshibki-4}

- бесконечный цикл из-за неверного обновления границы;
- потеря потенциального ответа;
- смешивание правил закрытого и полуоткрытого диапазона;
- использование `bisect` без понимания требуемой границы;
- считать `insort()` полностью логарифмической операцией: поиск позиции `O(log n)`, вставка в список `O(n)`.

## Неделя 8. Sorting и Intervals {#nedelya-8-sorting-i-intervals}

### Что изучить {#chto-izuchit-4}

- сортировку по одному и нескольким ключам;
- сортировку интервалов по началу или концу;
- объединение пересекающихся интервалов;
- вставку нового интервала;
- выбор непересекающихся интервалов;
- sweep line как дополнительный подход.

Для интервалов заранее договорись, что означают границы и считается ли касание пересечением.

### Практика {#praktika-5}

- `Sort Colors`;
- `Merge Intervals`;
- `Insert Interval`;
- `Non-overlapping Intervals`;
- `Meeting Rooms`.

### Частые ошибки {#chastye-oshibki-5}

- забыть отсортировать интервалы;
- сравнивать текущий интервал не с последним объединенным;
- потерять последний накопленный интервал;
- неверно обработать равные границы.

## Разобранные примеры {#razobrannye-primery}

### Two Pointers: пара с заданной суммой {#two-pointers-para-s-zadannoy-summoy}

Массив уже отсортирован. Левый указатель стоит на минимальном числе, правый - на максимальном.

```python
def find_pair(numbers: list[int], target: int) -> tuple[int, int] | None:
    left = 0  # Начинаем с самого маленького элемента.
    right = len(numbers) - 1  # Второй указатель ставим на самый большой.

    while left < right:
        current_sum = numbers[left] + numbers[right]

        if current_sum == target:
            # Возвращаем индексы, как только нашли нужную сумму.
            return left, right

        if current_sum < target:
            # Сумма слишком маленькая. Увеличить ее можно сдвигом left.
            left += 1
        else:
            # Сумма слишком большая. Уменьшаем ее сдвигом right.
            right -= 1

    return None  # Указатели встретились, подходящей пары нет.
```

Почему не нужно проверять остальные пары: если текущая сумма мала, любое число левее следующего `left` будет не больше текущего и не исправит ситуацию. Каждый указатель проходит массив не более одного раза.

- Время: `O(n)`.
- Дополнительная память: `O(1)`.

### Sliding Window: максимальная сумма окна {#sliding-window-maksimalnaya-summa-okna}

Нужно найти максимальную сумму среди всех непрерывных участков длины `window_size`.

```python
def max_window_sum(numbers: list[int], window_size: int) -> int:
    # Сумму первого окна вычисляем один раз.
    window_sum = sum(numbers[:window_size])
    best_sum = window_sum

    for right in range(window_size, len(numbers)):
        # Новый элемент входит в окно справа.
        window_sum += numbers[right]

        # Элемент, который оказался левее окна, удаляется из суммы.
        left = right - window_size
        window_sum -= numbers[left]

        # После сдвига сравниваем текущее окно с лучшим.
        best_sum = max(best_sum, window_sum)

    return best_sum
```

Без окна каждая сумма вычислялась бы заново за `O(window_size)`. Здесь после первого окна каждый сдвиг выполняется за `O(1)`.

- Время: `O(n)`.
- Дополнительная память: `O(1)`.

Перед использованием нужно договориться, что `1 <= window_size <= len(numbers)`.

### Binary Search: первая позиция не меньше target {#binary-search-pervaya-pozitsiya-ne-menshe-target}

```python
def lower_bound(numbers: list[int], target: int) -> int:
    left = 0
    right = len(numbers)  # Правая граница не входит в диапазон поиска.

    while left < right:
        middle = (left + right) // 2

        if numbers[middle] < target:
            # middle точно не подходит, исключаем его вместе с левой частью.
            left = middle + 1
        else:
            # middle может быть ответом, поэтому сохраняем его в диапазоне.
            right = middle

    # left указывает на первый элемент >= target или на len(numbers).
    return left
```

Инвариант: все позиции левее `left` уже точно меньше `target`, а искомая позиция остается внутри полуоткрытого диапазона `[left, right)`.

- Время: `O(log n)`.
- Дополнительная память: `O(1)`.

- объяснить, почему решение корректно;

## Задачи для самостоятельного решения {#zadachi-dlya-samostoyatelnogo-resheniya}

### Задача 1. Самая длинная серия единиц {#zadacha-1-samaya-dlinnaya-seriya-edinits}

Дан список из нулей и единиц. Можно заменить не более `k` нулей на единицы. Найди максимальную длину непрерывного участка из единиц.

```text
numbers = [1, 1, 0, 0, 1, 1, 1, 0]
k = 2
result = 7
```

Ограничение: решение должно работать за `O(n)`. Сформулируй состояние окна и условие сдвига левой границы.

```text
[[1, 3], [2, 6], [8, 10], [9, 12]] -> [[1, 6], [8, 12]]
```
