## Цель недели {#tsel-nedeli}

Научиться заменять перебор всех пар управляемым движением двух позиций.

После недели нужно уметь:

- распознавать задачи на два указателя;
- объяснять, почему один из указателей можно безопасно сдвинуть;
- работать с указателями навстречу друг другу;
- использовать указатель чтения и указатель записи;
- изменять список на месте;
- отличать Two Pointers от Sliding Window.

## Что такое два указателя {#chto-takoe-dva-ukazatelya}

Указатель в алгоритмической задаче - это обычная переменная с индексом.

```python
left = 0
right = len(numbers) - 1
```

Она показывает, с какой позицией списка алгоритм работает сейчас. Паттерн называется Two Pointers, потому что одновременно отслеживаются две позиции.

Главная идея: вместо того чтобы начинать новый полный проход для каждого элемента, указатели движутся только в нужную сторону и не возвращаются назад.

## Основные варианты {#osnovnye-varianty}

### Указатели движутся навстречу {#ukazateli-dvizhutsya-navstrechu}

Один указатель начинается слева, второй справа.

Подходит, когда:

- массив отсортирован;
- сравниваются симметричные элементы;
- нужно найти пару;
- нужно развернуть последовательность на месте.

### Указатели движутся в одну сторону {#ukazateli-dvizhutsya-v-odnu-storonu}

Один указатель читает элементы, второй отмечает позицию для записи.

Подходит, когда нужно:

- удалить дубликаты;
- переместить элементы;
- отфильтровать список на месте;
- разделить обработанную и необработанную части.

### Быстрый и медленный указатели {#bystryy-i-medlennyy-ukazateli}

Оба указателя движутся вперед, но с разной скоростью.

Так находят:

- середину связного списка;
- цикл;
- точку встречи периодических процессов.

Этот вариант подробно понадобится на этапе со связными списками.

## Пример 1. Проверка палиндрома {#primer-1-proverka-palindroma}

Палиндром одинаково читается слева направо и справа налево.

### Простая идея {#prostaya-ideya}

Можно развернуть строку и сравнить:

```python
def is_palindrome_with_copy(text: str) -> bool:
    return text == text[::-1]
```

Решение работает за `O(n)`, но срез создает новую строку размером `n`. Дополнительная память - `O(n)`.

### Решение двумя указателями {#reshenie-dvumya-ukazatelyami}

```python
def is_palindrome(text: str) -> bool:
    left = 0  # Первый символ.
    right = len(text) - 1  # Последний символ.

    while left < right:
        if text[left] != text[right]:
            # Несовпадение одной симметричной пары уже нарушает палиндром.
            return False

        # Текущая пара совпала. Переходим к следующей внутренней паре.
        left += 1
        right -= 1

    # Все симметричные пары совпали.
    return True
```

### Пошаговый разбор {#poshagovyy-razbor}

Для строки `"level"`:

| Шаг | `left` | `right` | Сравнение | Действие |
| --- | --- | --- | --- | --- |
| 1 | 0 | 4 | `l == l` | Сдвинуть оба указателя |
| 2 | 1 | 3 | `e == e` | Сдвинуть оба указателя |
| 3 | 2 | 2 | Указатели встретились | Вернуть `True` |

Каждый символ проверяется не более одного раза.

- Время: `O(n)`.
- Дополнительная память: `O(1)`.

## Пример 2. Пара с заданной суммой {#primer-2-para-s-zadannoy-summoy}

Дан отсортированный список. Нужно найти индексы двух чисел, сумма которых равна `target`.

### Почему сортировка важна {#pochemu-sortirovka-vazhna}

Если текущая сумма слишком маленькая, нужно взять число больше. Оно находится правее `left`.

Если сумма слишком большая, нужно взять число меньше. Оно находится левее `right`.

Без сортировки нельзя сделать такой вывод.

```python
def find_pair(numbers: list[int], target: int) -> tuple[int, int] | None:
    left = 0
    right = len(numbers) - 1

    while left < right:
        current_sum = numbers[left] + numbers[right]

        if current_sum == target:
            return left, right

        if current_sum < target:
            # Сумма мала. Правый элемент уже самый большой из доступных,
            # поэтому увеличиваем именно левый элемент.
            left += 1
        else:
            # Сумма велика. Левый элемент уже самый маленький из доступных,
            # поэтому уменьшаем правый элемент.
            right -= 1

    return None
```

### Пошаговый разбор {#poshagovyy-razbor-2}

```text
numbers = [1, 2, 4, 6, 10]
target = 8
```

| Шаг | Пара | Сумма | Действие |
| --- | --- | --- | --- |
| 1 | `1 + 10` | 11 | Сдвинуть `right` влево |
| 2 | `1 + 6` | 7 | Сдвинуть `left` вправо |
| 3 | `2 + 6` | 8 | Ответ найден |

Полный перебор проверил бы до `n²` пар. Здесь каждый указатель делает не более `n` сдвигов.

- Время: `O(n)`.
- Память: `O(1)`.

## Пример 3. Удаление дубликатов на месте {#primer-3-udalenie-dublikatov-na-meste}

Дан отсортированный список. Нужно переместить уникальные значения в начало и вернуть их количество.

Идея:

- `read` читает каждый элемент;
- `write` показывает, куда записать следующее новое значение;
- все элементы левее `write` уже уникальны.

```python
def remove_duplicates(numbers: list[int]) -> int:
    if not numbers:
        return 0

    write = 1  # Первый элемент уже считается уникальным.

    for read in range(1, len(numbers)):
        if numbers[read] == numbers[read - 1]:
            # Список отсортирован, поэтому равный предыдущему элемент - дубль.
            continue

        # Найдено новое значение. Записываем его после уникальной части.
        numbers[write] = numbers[read]
        write += 1

    # write одновременно является количеством уникальных элементов.
    return write
```

Для списка `[1, 1, 2, 2, 3]` функция вернет `3`, а первые три позиции будут содержать `[1, 2, 3]`.

Хвост списка после позиции `write` не имеет значения: условие требует только начало с уникальными элементами.

- Время: `O(n)`.
- Память: `O(1)`.

## Инвариант простыми словами {#invariant-prostymi-slovami}

Инвариант - утверждение, которое остается правильным после каждого шага цикла.

В примере с удалением дубликатов:

> Перед каждой новой итерацией элементы `numbers[:write]` уже уникальны и расположены правильно.

Инвариант помогает объяснить корректность решения. Если непонятно, что уже гарантированно обработано, указатели легко начать двигать случайным образом.

## Когда Two Pointers не подходит {#kogda-two-pointers-ne-podkhodit}

- Нужна произвольная пара в неотсортированном списке, а сортировать нельзя из-за индексов.
- Диапазон должен расширяться и сжиматься в зависимости от общего состояния: чаще нужен Sliding Window.
- Нужно быстро проверять уже просмотренные значения: возможно, нужен `set` или `dict`.
- Один из указателей должен постоянно возвращаться назад: линейного выигрыша может не быть.

## Частые ошибки {#chastye-oshibki}

1. Забыть сдвинуть указатель в одной из веток и получить бесконечный цикл.
2. Использовать условие `left <= right`, когда один элемент нельзя брать дважды.
3. Потерять исходные индексы после сортировки.
4. Сравнивать `numbers[read]` с неправильной позицией при удалении дубликатов.
5. Не объяснить, почему выбранный сдвиг не удаляет возможный ответ.
6. Создать новый список в задаче, где требуется изменение на месте.

## План занятий {#plan-zanyatiy}

1. Реализуй палиндром и разворот списка.
2. Реши поиск пары в отсортированном массиве.
3. Реализуй удаление дубликатов и перемещение нулей.
4. Для каждого решения проговори инвариант.
5. Повтори одну задачу через день без просмотра кода.

## Задачи для самостоятельного решения {#zadachi-dlya-samostoyatelnogo-resheniya}

### Задача 1. Контейнер с водой {#zadacha-1-konteyner-s-vodoy}

Дан список высот вертикальных линий. Выбери две линии так, чтобы они вместе с осью образовали контейнер максимальной площади.

```text
[1, 8, 6, 2, 5, 4, 8, 3, 7] -> 49
```

Требования:

- решение за `O(n)`;
- объясни, почему нужно сдвигать указатель с меньшей высотой;
- дополнительная память `O(1)`.

### Задача 2. Три числа с нулевой суммой {#zadacha-2-tri-chisla-s-nulevoy-summoy}

Верни все уникальные тройки чисел, сумма которых равна нулю.

```text
[-1, 0, 1, 2, -1, -4] -> [[-1, -1, 2], [-1, 0, 1]]
```

Подсказка: сначала отсортируй список, зафиксируй один элемент, а оставшуюся пару ищи двумя указателями. Отдельно продумай пропуск дубликатов.
