## Зачем анализировать сложность {#zachem-analizirovat-slozhnost}

Одна задача может иметь несколько правильных решений, но они будут по-разному работать на больших данных.

Например, нужно проверить, есть ли в списке два числа с заданной суммой:

- перебрать все пары - `O(n²)`;
- запоминать уже просмотренные числа в `set` - в среднем `O(n)`.

На десяти элементах разница почти незаметна. На миллионе элементов полный перебор пар становится непрактичным. Анализ сложности позволяет оценить такое поведение без запуска программы на всех возможных входных данных.

## Что такое размер входных данных {#chto-takoe-razmer-vkhodnykh-dannykh}

Обычно размер входа обозначают буквой `n`.

Примеры:

- для списка `n` - количество элементов;
- для строки `n` - количество символов;
- для матрицы могут использоваться `rows` и `columns`;
- для графа отдельно используют `V` - количество вершин и `E` - количество ребер.

Сначала определи, что именно растет. Без этого оценка сложности теряет смысл.

```python
def contains_zero(numbers: list[int]) -> bool:
    for number in numbers:
        if number == 0:
            return True
    return False
```

Здесь `n` - длина `numbers`.

- Лучший случай: первый элемент равен нулю, выполнится одна проверка.
- Худший случай: нуля нет или он находится в конце, будут проверены все `n` элементов.
- Для верхней оценки времени указывают `O(n)`.

## Временная и пространственная сложность {#vremennaya-i-prostranstvennaya-slozhnost}

### Временная сложность {#vremennaya-slozhnost}

Временная сложность показывает, как растет количество операций при увеличении входа.

Она не означает точное количество секунд. На реальное время также влияют процессор, версия Python, типы объектов и другие детали. Big O описывает характер роста.

### Пространственная сложность {#prostranstvennaya-slozhnost}

Пространственная сложность показывает, сколько дополнительной памяти требуется алгоритму.

```python
def doubled(numbers: list[int]) -> list[int]:
    result = []

    for number in numbers:
        result.append(number * 2)

    return result
```

- Время: `O(n)`, потому что обрабатывается каждый элемент.
- Дополнительная память: `O(n)`, потому что создается новый список из `n` элементов.

Если алгоритм меняет исходный список и использует несколько обычных переменных, дополнительная память часто равна `O(1)`.

## Основные классы сложности {#osnovnye-klassy-slozhnosti}

| Сложность | Как растет работа | Типичный пример |
| --- | --- | --- |
| `O(1)` | Не зависит от `n` | Получение элемента списка по индексу |
| `O(log n)` | Вход многократно уменьшается | Бинарный поиск |
| `O(n)` | Пропорционально размеру входа | Один полный проход |
| `O(n log n)` | Немного быстрее квадратичного роста | Эффективная сортировка |
| `O(n²)` | Для каждого элемента просматривается весь вход | Перебор всех пар |
| `O(2ⁿ)` | На каждом шаге появляются несколько ветвей | Перебор всех подмножеств |
| `O(n!)` | Перебираются все перестановки | Полный перебор порядка элементов |

При больших `n` разница между классами важнее небольших различий внутри одного класса.

## O(1): постоянное время {#o-1-postoyannoe-vremya}

Количество операций не зависит от длины списка.

```python
def first(numbers: list[int]) -> int | None:
    if not numbers:
        return None

    return numbers[0]
```

Проверка списка и чтение элемента по индексу имеют постоянную стоимость, поэтому итоговая сложность - `O(1)`.

`O(1)` не означает одну машинную операцию. Это означает, что количество работы не растет вместе с `n`.

## O(n): линейное время {#o-n-lineynoe-vremya}

```python
def total(numbers: list[int]) -> int:
    result = 0

    for number in numbers:
        result += number

    return result
```

Цикл выполняется `n` раз, поэтому время - `O(n)`. Переменные `result` и `number` не создают коллекцию размером `n`, поэтому дополнительная память - `O(1)`.

## Последовательные циклы складываются {#posledovatelnye-tsikly-skladyvayutsya}

```python
def show_twice(numbers: list[int]) -> None:
    for number in numbers:
        print(number)  # выводит очередной элемент numbers

    for number in numbers:
        print(number)  # повторно выводит очередной элемент numbers
```

Первый цикл выполняет `n` итераций, второй - еще `n`:

```text
O(n) + O(n) = O(2n) = O(n)
```

Константа `2` отбрасывается, потому что характер роста остается линейным.

## Вложенные циклы перемножаются {#vlozhennye-tsikly-peremnozhayutsya}

```python
def all_pairs(numbers: list[int]) -> list[tuple[int, int]]:
    pairs = []

    for left in numbers:
        for right in numbers:
            pairs.append((left, right))

    return pairs
```

Внешний цикл выполняется `n` раз. Для каждой его итерации внутренний цикл также выполняется `n` раз:

```text
n * n = n²
```

Время - `O(n²)`. Память тоже `O(n²)`, потому что в `pairs` сохраняются все пары.

## Зависимые границы цикла {#zavisimye-granitsy-tsikla}

Количество итераций внутреннего цикла может зависеть от внешнего:

```python
def unique_pairs(numbers: list[int]) -> list[tuple[int, int]]:
    pairs = []

    for left_index in range(len(numbers)):
        for right_index in range(left_index + 1, len(numbers)):
            pairs.append((numbers[left_index], numbers[right_index]))

    return pairs
```

Будет создано примерно `n * (n - 1) / 2` пар. После отбрасывания констант и младших членов остается `O(n²)`.

Не каждый вложенный цикл автоматически означает `O(n²)`. Нужно определить, сколько раз реально двигаются указатели или выполняется тело цикла.

## O(log n): вход уменьшается {#o-log-n-vkhod-umenshaetsya}

```python
def count_halvings(number: int) -> int:
    steps = 0

    while number > 1:
        number //= 2
        steps += 1

    return steps
```

На каждом шаге `number` уменьшается в два раза. Для значения `1024` потребуется только 10 делений. Сложность - `O(log n)`.

Основание логарифма в Big O обычно не указывают: логарифмы с разными постоянными основаниями отличаются постоянным множителем.

## O(n log n): сортировка и проход {#o-n-log-n-sortirovka-i-prokhod}

```python
def sorted_unique(numbers: list[int]) -> list[int]:
    sorted_numbers = sorted(numbers)
    result = []

    for number in sorted_numbers:
        if not result or result[-1] != number:
            result.append(number)

    return result
```

- `sorted(numbers)` - `O(n log n)`.
- Проход по отсортированному списку - `O(n)`.
- Итог: `O(n log n + n) = O(n log n)`.
- Дополнительная память - `O(n)` для нового списка и результата.

## Отбрасывание констант и младших членов {#otbrasyvanie-konstant-i-mladshikh-chlenov}

Для оценки роста оставляют наиболее быстро растущий член:

```text
O(5)            -> O(1)
O(3n)           -> O(n)
O(n + 100)      -> O(n)
O(n² + n)       -> O(n²)
O(2n log n + n) -> O(n log n)
```

Это не означает, что константы никогда не важны. Они влияют на реальную скорость, но Big O используется прежде всего для сравнения роста алгоритмов.

## Несколько независимых входов {#neskolko-nezavisimykh-vkhodov}

Если функция принимает две коллекции разного размера, не нужно автоматически заменять их одной буквой `n`.

```python
def has_common_value(left: list[int], right: list[int]) -> bool:
    for left_value in left:
        for right_value in right:
            if left_value == right_value:
                return True

    return False
```

Если длины списков равны `n` и `m`, сложность - `O(n * m)`.

## Рекурсия и стек вызовов {#rekursiya-i-stek-vyzovov}

```python
def factorial(number: int) -> int:
    if number <= 1:
        return 1

    return number * factorial(number - 1)
```

Функция делает `n` вызовов:

- время - `O(n)`;
- память стека вызовов - `O(n)`.

Даже если функция не создает список, рекурсивные вызовы занимают память.

Для ветвящейся рекурсии нужно учитывать количество ветвей и глубину дерева вызовов. Наивное вычисление Fibonacci выполняет повторяющиеся вычисления и имеет экспоненциальную сложность.

## Амортизированная стоимость {#amortizirovannaya-stoimost}

Добавление в конец списка через `append()` обычно выполняется за `O(1)`. Иногда Python должен выделить более крупный участок памяти и перенести элементы, поэтому отдельный вызов может быть дороже.

Если рассмотреть длинную последовательность добавлений, редкие дорогие расширения распределяются между множеством дешевых операций. Поэтому говорят, что `append()` имеет **амортизированную сложность `O(1)`**.

## Обмен времени на память {#obmen-vremeni-na-pamyat}

Дополнительная память часто позволяет уменьшить время.

```python
def has_duplicate(numbers: list[int]) -> bool:
    seen = set()

    for number in numbers:
        if number in seen:
            return True

        seen.add(number)

    return False
```

- Время - в среднем `O(n)`.
- Дополнительная память - `O(n)`.

Без `set` можно сравнивать все пары и не создавать дополнительную коллекцию, но время станет `O(n²)`. Такой выбор называется time-space tradeoff.

## Big O, Omega и Theta {#big-o-omega-i-theta}

- **Big O** описывает асимптотическую верхнюю границу роста.
- **Big Omega** описывает нижнюю границу.
- **Big Theta** означает, что верхняя и нижняя границы совпадают по порядку роста.

На собеседованиях под вопросом «какая сложность» чаще всего ожидают Big O для худшего или типичного оговоренного случая. Если лучший и худший случаи сильно отличаются, назови их отдельно.

## Частые ошибки {#chastye-oshibki}

1. Считать два последовательных цикла квадратичными.
2. Считать любой вложенный цикл квадратичным, не проверив движение границ.
3. Учитывать только циклы и забывать стоимость вызванных операций.
4. Считать срез списка операцией `O(1)`.
5. Не учитывать память нового списка, словаря или множества.
6. Не учитывать стек рекурсивных вызовов.
7. Говорить `O(n)`, не объясняя, что означает `n`.
8. Складывать разные размеры входа как `O(n²)` вместо `O(n * m)`.

## Практика {#praktika}

Для каждого фрагмента определи время и дополнительную память:

```python
# 1
value = numbers[-1]

# 2
for number in numbers:
    print(number)  # выводит очередной элемент numbers

# 3
for number in numbers:
    for other in numbers:
        print(number, other)  # выводит очередную упорядоченную пару

# 4
copy = numbers[:]

# 5
result = sorted(numbers)

# 6
while number > 1:
    number //= 2

# 7
for left in first:
    for right in second:
        print(left, right)  # выводит очередную пару из first и second
```

Ответы:

| Фрагмент | Время | Дополнительная память |
| --- | --- | --- |
| 1 | `O(1)` | `O(1)` |
| 2 | `O(n)` | `O(1)` |
| 3 | `O(n²)` | `O(1)` без учета вывода |
| 4 | `O(n)` | `O(n)` |
| 5 | `O(n log n)` | зависит от реализации, для оценки решения учитывай новый список `O(n)` |
| 6 | `O(log n)` | `O(1)` |
| 7 | `O(n * m)` | `O(1)` без учета вывода |
