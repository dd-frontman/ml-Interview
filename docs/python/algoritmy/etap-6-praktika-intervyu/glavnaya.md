## Цель этапа {#tsel-etapa}

Во время изучения тема задачи известна заранее. На собеседовании никто не скажет, что нужно применить Sliding Window, DFS или Dynamic Programming.

Последний этап учит:

- самостоятельно распознавать паттерн;
- объяснять ход мысли;
- укладываться во время;
- проверять код без запуска;
- исправлять ошибки по собственным тестам;
- повторять слабые темы на основе фактов, а не ощущений.

Продолжительность: **три недели**.

| Неделя | Работа | Результат |
| --- | --- | --- |
| 22 | Mixed Problems | Выбор подхода без названия темы |
| 23 | Mock Interviews | Два полных пробных интервью |
| 24 | Финальная диагностика | Исправление слабых мест и итоговая оценка |

## Неделя 22. Mixed Problems {#nedelya-22-mixed-problems}

Убери группировку задач по темам. Составь случайную выборку из уже изученных направлений.

Рекомендуемый набор недели:

- 2 задачи на массивы, строки или hashing;
- 1 задача на Two Pointers или Sliding Window;
- 1 задача на Binary Search;
- 1 задача на stack, queue или linked list;
- 1 задача на tree или graph;
- 1 задача на heap или intervals;
- 1 задача на greedy или DP.

Всего: **8-10 смешанных задач**.

## Алгоритм решения на интервью {#algoritm-resheniya-na-intervyu}

Для каждой задачи соблюдай последовательность.

### 1. Уточнить условие {#1-utochnit-uslovie}

Спроси:

- какие размеры входа возможны;
- могут ли быть пустые данные;
- есть ли отрицательные числа и дубликаты;
- отсортирован ли вход;
- можно ли менять входную коллекцию;
- что возвращать, если ответа нет.

Не придумывай ограничения, которых нет в условии.

### 2. Разобрать пример {#2-razobrat-primer}

Пройди небольшой пример вручную. Добавь собственный граничный случай.

Хороший пример должен помогать проверить алгоритм, а не только повторять пример из условия.

### 3. Предложить brute force {#3-predlozhit-brute-force}

Сначала сформулируй самое простое корректное решение.

Это дает:

- точку отсчета для оптимизации;
- понимание повторяющейся работы;
- запасной вариант, если оптимальное решение не найдено.

### 4. Найти узкое место {#4-nayti-uzkoe-mesto}

Спроси:

- какой поиск повторяется;
- какие данные пересчитываются;
- можно ли сохранить предыдущий результат;
- поможет ли сортировка;
- нужна ли быстрая проверка наличия;
- есть ли непрерывное окно;
- является ли пространство ответа монотонным;
- выглядит ли вход как дерево или граф.

### 5. Объяснить оптимальное решение {#5-obyasnit-optimalnoe-reshenie}

До кода проговори:

- структуру данных;
- состояние;
- порядок обработки;
- инвариант;
- условие завершения;
- временную и пространственную сложность.

Если объяснение распадается, код писать рано.

### 6. Написать код {#6-napisat-kod}

Во время написания:

- используй понятные имена;
- не усложняй структуру заранее;
- не добавляй оптимизацию без необходимости;
- разделяй логические шаги;
- проговаривай важные проверки.

### 7. Проверить решение {#7-proverit-reshenie}

Пройди код построчно на примере. Обязательно проверь:

- пустой вход;
- один элемент;
- минимальный допустимый ответ;
- отсутствие ответа;
- повторяющиеся значения;
- ответ в начале или конце;
- ветку, которая не выполнялась в основном примере.

## Как выбирать паттерн {#kak-vybirat-pattern}

| Вопрос | Возможное направление |
| --- | --- |
| Нужен быстрый поиск по уже увиденным значениям? | `dict` или `set` |
| Рассматривается непрерывный диапазон? | Sliding Window или Prefix Sum |
| Данные отсортированы? | Two Pointers или Binary Search |
| Нужна последняя незавершенная операция? | Stack |
| Нужен порядок по уровням или кратчайший путь без весов? | BFS |
| Нужно исследовать все ветви? | DFS или Backtracking |
| Нужен лучший из поступающих элементов? | Heap |
| Есть повторяющиеся подзадачи? | Dynamic Programming |
| Можно доказать локально лучший выбор? | Greedy |

## Неделя 23. Mock Interviews {#nedelya-23-mock-interviews}

Проведи два интервью продолжительностью 45-60 минут.

### Условия {#usloviya}

- задача заранее неизвестна;
- нельзя искать готовое решение;
- код пишется в обычном редакторе без автотестов;
- нужно говорить вслух;
- интервьюер дает подсказки только после явного затруднения;
- после завершения сохраняются код, время и замечания.

### Оценочная таблица {#otsenochnaya-tablitsa}

Оцени каждый пункт от 0 до 2:

| Критерий | 0 | 1 | 2 |
| --- | --- | --- | --- |
| Понимание условия | Не понял ограничения | Понял после подсказки | Сам уточнил важные детали |
| Примеры | Не проверял | Проверил основной | Добавил граничные случаи |
| Подход | Нет корректной идеи | Идея после подсказки | Сам нашел и обосновал |
| Код | Не завершен | Есть небольшие ошибки | Корректный и читаемый |
| Сложность | Не названа | Названа с ошибкой | Правильно объяснена |
| Проверка | Ошибки не найдены | Частичная проверка | Сам нашел и исправил |
| Коммуникация | Долгое молчание | Объяснение фрагментами | Последовательный ход мысли |

Максимум - 14 баллов.

- 11-14: уверенный результат;
- 8-10: рабочий уровень, но есть конкретные пробелы;
- 5-7: требуется повторение нескольких базовых тем;
- 0-4: нужно вернуться к более ранним этапам.

Оценка нужна для выбора следующей практики, а не для создания ложной гарантии прохождения собеседования.

## Разбор после интервью {#razbor-posle-intervyu}

После каждого интервью письменно ответь:

1. Где было потрачено больше всего времени?
2. Какой сигнал паттерна был пропущен?
3. Была ли ошибка в идее или только в коде?
4. Какой тест мог обнаружить ошибку раньше?
5. Какая подсказка понадобилась?
6. Смогу ли я решить эту задачу через неделю с чистого листа?

Не ограничивайся записью «не знал решение». Найди конкретный пробел: структура данных, инвариант, граничный случай или реализация.

## Неделя 24. Финальная диагностика {#nedelya-24-finalnaya-diagnostika}

Проведи еще два или три пробных интервью. Между ними повторяй только те темы, которые подтверждены ошибками.

### Матрица слабых мест {#matritsa-slabykh-mest}

| Проблема | Что делать |
| --- | --- |
| Не узнаю паттерн | Решать смешанные задачи и проговаривать сигналы |
| Знаю идею, не пишу код | Реализовать шаблон с чистого листа несколько раз |
| Ошибки в границах | Добавлять таблицу индексов и минимальные примеры |
| Не называю сложность | Анализировать каждую строку после решения |
| Не замечаю ошибку | Делать ручной trace до запуска |
| Не укладываюсь во время | Ограничить этапы таймером и раньше фиксировать brute force |
| Теряюсь при общении | Практиковаться вслух с интервьюером или записью экрана |

## Разобранный пример интервью {#razobrannyy-primer-intervyu}

Задача: найти длину самой длинной подстроки без повторяющихся символов.

### 1. Уточнение {#1-utochnenie}

- Подстрока должна быть непрерывной.
- Пустая строка должна вернуть `0`.
- Учитываются все переданные символы.

Слово «подстрока» подсказывает непрерывный диапазон. Нужно поддерживать окно без повторов.

### 2. Brute force {#2-brute-force}

Можно начать каждую подстроку с каждой позиции и проверять символы до первого повтора. Такое решение может потребовать `O(n²)` времени.

Повторяющаяся работа: одни и те же символы проверяются много раз.

### 3. Оптимизация {#3-optimizatsiya}

Храним последнюю позицию каждого символа. При повторе переносим левую границу сразу за предыдущую позицию символа.

```python
def longest_unique_substring(text: str) -> int:
    last_index: dict[str, int] = {}
    left = 0
    best_length = 0

    for right, character in enumerate(text):
        if character in last_index:
            # Граница не должна двигаться назад. Предыдущее появление
            # символа может уже находиться левее текущего окна.
            left = max(left, last_index[character] + 1)

        # Обновляем позицию символа после обработки возможного повтора.
        last_index[character] = right

        # Окно включает обе границы, поэтому добавляем единицу.
        current_length = right - left + 1
        best_length = max(best_length, current_length)

    return best_length
```

### 4. Проверка {#4-proverka}

Для строки `"abba"`:

| `right` | Символ | `left` после обработки | Лучший результат |
| --- | --- | --- | --- |
| 0 | `a` | 0 | 1 |
| 1 | `b` | 0 | 2 |
| 2 | `b` | 2 | 2 |
| 3 | `a` | 2 | 2 |

Вызов `max(left, ...)` не позволяет левой границе вернуться с позиции `2` на позицию `1` при последнем символе `a`.

- Время: `O(n)`.
- Память: `O(k)`, где `k` - количество различных символов.

Такой разбор показывает интервьюеру не только код, но и переход от простого решения к оптимальному.

## Система повторения {#sistema-povtoreniya}

Сложную задачу решай повторно:

- через один день;
- через одну неделю;
- через три недели.

Повторение считается успешным, только если решение написано с чистого листа и ты можешь объяснить паттерн, инвариант, время и память.

Если запомнился только код, возьми другую задачу того же типа.

## Финальный критерий готовности {#finalnyy-kriteriy-gotovnosti}

Можно начинать реальные собеседования, когда ты:

- решаешь не менее 80% новых Easy за 15-20 минут;
- решаешь около 50-60% новых Medium по изученным темам за 30-40 минут;
- объясняешь подход до кода;
- правильно называешь время и память;
- самостоятельно составляешь тесты;
- переходишь от brute force к оптимизации;
- решаешь смешанные задачи без названия паттерна;
- исправляешь большую часть ошибок по собственному trace;
- прошел минимум шесть пробных интервью за весь курс;
- не имеешь повторяющейся критической ошибки в последних трех интервью.

Это учебные ориентиры. Требования конкретной компании могут быть выше, ниже или смещены в сторону системного дизайна, Python, SQL или ML.

## Задачи для самостоятельного решения {#zadachi-dlya-samostoyatelnogo-resheniya}

Эти задачи выполняются в режиме пробного интервью: 45 минут, без поиска решения и без запуска тестов до завершения ручной проверки.

### Задача 1. Произведение элементов кроме текущего {#zadacha-1-proizvedenie-elementov-krome-tekushchego}

Для каждого элемента списка верни произведение всех остальных элементов.

```text
[1, 2, 3, 4] -> [24, 12, 8, 6]
```

Нельзя использовать деление. Основная цель - решение за `O(n)` времени. Объясни, какие данные можно накопить слева и справа.

### Задача 2. Можно ли закончить все курсы {#zadacha-2-mozhno-li-zakonchit-vse-kursy}

Есть `number_of_courses` курсов и пары зависимостей `[course, prerequisite]`. Определи, можно ли пройти все курсы.

Перед кодом:

1. Выбери представление графа.
2. Объясни, что означает цикл в этом условии.
3. Выбери DFS с тремя состояниями или алгоритм Кана.
4. Назови сложность через количество курсов и зависимостей.
