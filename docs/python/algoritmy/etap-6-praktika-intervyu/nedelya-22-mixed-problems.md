## Цель недели {#tsel-nedeli}

Научиться выбирать подход без заранее известной темы. На предыдущих этапах заголовок главы подсказывал паттерн. Теперь задачи должны поступать в случайном порядке.

После недели нужно уметь:

- выделять ограничения и требуемый результат;
- предлагать корректный brute force;
- находить повторяющуюся работу;
- выбирать структуру данных по требуемым операциям;
- формулировать инвариант до кода;
- решать задачу под ограничением времени;
- проверять код без запуска;
- классифицировать собственные ошибки;
- повторять задачу с чистого листа.

## Почему смешанная практика обязательна {#pochemu-smeshannaya-praktika-obyazatelna}

Когда все задачи находятся в разделе Sliding Window, основная подсказка уже дана. На интервью условие не сообщает:

```text
используй Prefix Sum и Hash Map
```

Нужно самостоятельно пройти путь:

```text
условие -> ограничения -> brute force -> узкое место -> паттерн
```

Смешанная практика проверяет не память на конкретный код, а способность распознать структуру задачи.

## Набор задач на неделю {#nabor-zadach-na-nedelyu}

Рекомендуемый объем — `8–10` новых задач:

| Направление | Количество |
| --- | --- |
| Arrays, Strings, Hashing | 2 |
| Two Pointers или Sliding Window | 1 |
| Prefix Sum или Binary Search | 1 |
| Stack, Queue или Linked List | 1 |
| Trees или Graphs | 1–2 |
| Heap или Intervals | 1 |
| Greedy или DP | 1–2 |

Не подписывай тему рядом с названием задачи. Сохрани соответствие в отдельном файле и открывай его только после решения.

## Как выбирать задачи {#kak-vybirat-zadachi}

Хорошая смешанная выборка:

- содержит знакомые паттерны на новых условиях;
- включает Easy и Medium;
- не состоит только из любимых тем;
- содержит хотя бы одну задачу из слабой области;
- не повторяет подряд одинаковые паттерны;
- включает задачи, где очевидный первый подход не оптимален.

Не нужно брать десять Hard. Цель недели — стабильный процесс решения, а не максимальная сложность.

## Режим одной задачи {#rezhim-odnoy-zadachi}

Для Medium выдели `40–45` минут:

| Этап | Время |
| --- | --- |
| Условие и вопросы | 3–5 минут |
| Примеры и brute force | 5–8 минут |
| Поиск оптимизации | 8–12 минут |
| Код | 12–15 минут |
| Ручная проверка | 5 минут |

Время является ориентиром. Если через 15 минут нет даже корректного brute force, остановись и заново сформулируй вход, выход и маленький пример.

## Шаг 1. Уточнить условие {#shag-1-utochnit-uslovie}

До выбора паттерна выясни:

- размер входа;
- допустимы ли пустые данные;
- есть ли отрицательные числа;
- возможны ли дубликаты;
- отсортирован ли вход;
- можно ли изменять исходную коллекцию;
- нужен один ответ или все ответы;
- существует ли гарантированное решение;
- что возвращать при отсутствии ответа.

Размер входа помогает оценить допустимую сложность:

| Размер | Возможный ориентир |
| --- | --- |
| До `20` | Экспоненциальный перебор может быть допустим |
| До `10³` | `O(n²)` иногда допустимо |
| До `10⁵` | Обычно нужен `O(n)` или `O(n log n)` |
| До `10⁹` как диапазон ответа | Возможен бинарный поиск по ответу |

Это не жесткие правила: реальное ограничение зависит от языка и операции внутри цикла.

## Шаг 2. Разобрать пример {#shag-2-razobrat-primer}

Не ограничивайся примером из условия. Добавь:

- минимальный вход;
- случай без ответа;
- дубликаты;
- отрицательные значения, если разрешены;
- ответ в начале или в конце;
- случай, ломающий очевидную стратегию.

Пример должен помогать проверить гипотезу о решении.

## Шаг 3. Предложить brute force {#shag-3-predlozhit-brute-force}

Brute force нужен как точка отсчета.

Проговори:

1. Какие варианты перебираются.
2. Как проверяется один вариант.
3. Сколько вариантов существует.
4. Какова общая сложность.

Например, для поиска пары с заданной суммой:

```text
перебрать все пары: O(n²)
для каждого первого числа проверить все числа справа
```

После этого видно узкое место: повторный поиск дополнения.

## Шаг 4. Найти повторяющуюся работу {#shag-4-nayti-povtoryayushchuyusya-rabotu}

Полезные вопросы:

- Повторяется ли поиск одного значения?
- Пересчитывается ли сумма диапазона?
- Сравниваются ли одни и те же пары?
- Исследуется ли одна вершина несколько раз?
- Вычисляется ли одно состояние рекурсии повторно?
- Можно ли убрать часть вариантов сортировкой?
- Достаточно ли хранить лучший кандидат?

Оптимизация обычно появляется из конкретной повторяющейся операции, а не из угадывания названия паттерна.

## Карта сигналов {#karta-signalov}

| Сигнал | Возможное направление |
| --- | --- |
| Быстро проверить ранее встреченное значение | `dict` или `set` |
| Непрерывный диапазон | Sliding Window или Prefix Sum |
| Отсортированные данные | Two Pointers или Binary Search |
| Монотонное условие ответа | Binary Search on Answer |
| Последняя незавершенная операция | Stack |
| Ближайшее состояние без весов | BFS |
| Все ветви или компоненты | DFS |
| Лучший из поступающих кандидатов | Heap |
| Пересекающиеся интервалы | Sorting + Intervals |
| Повторяющиеся подзадачи | DP |
| Все варианты решения | Backtracking |
| Локальный выбор можно доказать | Greedy |

Таблица дает гипотезы, а не готовый ответ. Гипотезу нужно проверить на примере и ограничениях.

## Шаг 5. Объяснить решение до кода {#shag-5-obyasnit-reshenie-do-koda}

Хорошее объяснение отвечает на вопросы:

1. Какая структура данных используется?
2. Что хранится в ней?
3. В каком порядке обрабатывается вход?
4. Какой инвариант сохраняется?
5. Когда обновляется ответ?
6. Почему алгоритм не пропускает решение?
7. Каковы время и память?

Если непонятно, что означает переменная или состояние, код почти наверняка будет трудно проверить.

## Пример 1. Subarray Sum Equals K {#primer-1-subarray-sum-equals-k}

Задача: посчитать непрерывные подмассивы с суммой `target`.

### Brute force {#brute-force}

Начать подмассив с каждого индекса и расширять вправо. Это занимает `O(n²)`.

Sliding Window не подходит в общем случае, потому что отрицательные числа нарушают монотонность суммы: расширение окна может уменьшить сумму.

### Переход к Prefix Sum {#perekhod-k-prefix-sum}

Пусть текущая префиксная сумма равна `prefix_sum`.

Подмассив имеет сумму `target`, если раньше существовала сумма:

```text
prefix_sum - target
```

Нужно знать не только факт ее существования, но и количество появлений.

```python
def count_subarrays_with_sum(
    numbers: list[int],
    target: int,
) -> int:
    prefix_count = {0: 1}
    prefix_sum = 0
    result = 0

    for number in numbers:
        prefix_sum += number

        required_prefix = prefix_sum - target
        result += prefix_count.get(required_prefix, 0)

        # Текущая сумма становится доступна только после подсчета,
        # чтобы не использовать одну позицию как начало и конец.
        prefix_count[prefix_sum] = prefix_count.get(prefix_sum, 0) + 1

    return result
```

### Зачем запись 0: 1 {#zachem-zapis-0-1}

Она представляет пустой префикс до начала массива. Благодаря этому подмассив, начинающийся с индекса `0`, учитывается обычной формулой.

- Время: `O(n)`.
- Память: `O(n)`.

## Пример 2. Поиск в повернутом массиве {#primer-2-poisk-v-povernutom-massive}

Дан отсортированный массив, который повернули в неизвестной позиции. Нужно найти `target` за `O(log n)`.

Пример:

```text
[4, 5, 6, 7, 0, 1, 2]
```

В каждой итерации хотя бы одна половина остается отсортированной.

```python
def search_rotated(numbers: list[int], target: int) -> int:
    left = 0
    right = len(numbers) - 1

    while left <= right:
        middle = left + (right - left) // 2

        if numbers[middle] == target:
            return middle

        if numbers[left] <= numbers[middle]:
            # Левая половина отсортирована.
            if numbers[left] <= target < numbers[middle]:
                right = middle - 1
            else:
                left = middle + 1
        else:
            # Правая половина отсортирована.
            if numbers[middle] < target <= numbers[right]:
                left = middle + 1
            else:
                right = middle - 1

    return -1
```

### Инвариант {#invariant}

Если `target` существует, он находится внутри текущего закрытого диапазона `[left, right]`.

На каждом шаге определяется отсортированная половина и проверяется, входит ли `target` в ее диапазон значений.

- Время: `O(log n)`.
- Память: `O(1)`.

Этот вариант предполагает уникальные значения. Дубликаты требуют дополнительной обработки и могут ухудшить худшую сложность.

## Пример 3. Top K Frequent Elements {#primer-3-top-k-frequent-elements}

Нужно вернуть `k` самых частых значений.

Сначала строится частотный словарь. Затем поддерживается min-heap размера `k`.

```python
import heapq


def top_k_frequent(numbers: list[int], k: int) -> list[int]:
    frequency: dict[int, int] = {}

    for number in numbers:
        frequency[number] = frequency.get(number, 0) + 1

    heap: list[tuple[int, int]] = []

    for number, count in frequency.items():
        heapq.heappush(heap, (count, number))

        if len(heap) > k:
            # Удаляем наименее частый элемент среди кандидатов.
            heapq.heappop(heap)

    return [number for _, number in heap]
```

Если `u` — количество уникальных значений:

- подсчет частот: `O(n)`;
- работа кучи: `O(u log k)`;
- память: `O(u + k)`.

Порядок элементов ответа здесь не гарантирован. Если условие требует конкретный порядок, его нужно обработать отдельно.

## Пример 4. Lowest Common Ancestor в бинарном дереве {#primer-4-lowest-common-ancestor-v-binarnom-dereve}

Нужно найти самый нижний узел, являющийся предком двух заданных узлов.

```python
def lowest_common_ancestor(
    root: "TreeNode | None",
    first: "TreeNode",
    second: "TreeNode",
) -> "TreeNode | None":
    if root is None or root is first or root is second:
        return root

    left_result = lowest_common_ancestor(root.left, first, second)
    right_result = lowest_common_ancestor(root.right, first, second)

    if left_result is not None and right_result is not None:
        # Узлы найдены в разных поддеревьях.
        return root

    if left_result is not None:
        return left_result

    return right_result
```

### Что возвращает рекурсивный вызов {#chto-vozvrashchaet-rekursivnyy-vyzov}

Для каждого поддерева функция возвращает:

- `None`, если ни один искомый узел не найден;
- найденный узел или уже найденного общего предка.

Если левый и правый вызовы вернули результат, пути к узлам расходятся в текущем корне.

- Время: `O(n)`.
- Стек: `O(h)`.

Условие обычно гарантирует наличие обоих узлов. Если такой гарантии нет, решение должно отдельно подтвердить присутствие обоих.

## Ручная проверка без запуска {#ruchnaya-proverka-bez-zapuska}

После написания кода создай таблицу переменных.

Для цикла фиксируй:

- номер итерации;
- ключевые указатели или индексы;
- содержимое структуры данных;
- изменение ответа;
- условие следующего шага.

Для рекурсии фиксируй:

- аргументы вызова;
- базовый случай;
- значения, возвращенные детьми;
- итог текущего вызова.

Не проверяй код только глазами. Выполняй его как интерпретатор.

## Журнал задач {#zhurnal-zadach}

Для каждой попытки записывай:

| Поле | Что указать |
| --- | --- |
| Задача | Название и ссылка |
| Дата | Когда решалась |
| Время | До рабочего решения |
| Brute force | Идея и сложность |
| Оптимизация | Паттерн и инвариант |
| Подсказки | Что потребовалось |
| Ошибка | Конкретная причина |
| Повтор | Даты следующего решения |

Запись «не решил» бесполезна. Нужна конкретная причина: не заметил Prefix Sum, перепутал границы, не смог реализовать heap или неверно оценил сложность.

## Категории ошибок {#kategorii-oshibok}

### Ошибка распознавания {#oshibka-raspoznavaniya}

Решение известно после подсказки, но самостоятельно паттерн не найден.

Действие: решить две другие задачи с тем же скрытым сигналом, не подписывая тему.

### Ошибка алгоритма {#oshibka-algoritma}

Паттерн выбран правильно, но переход или инвариант неверен.

Действие: построить контрпример и переписать объяснение до кода.

### Ошибка реализации {#oshibka-realizatsii}

Идея верна, но код ломается на границе, индексе или обновлении состояния.

Действие: выписать минимальный тест и сделать построчный trace.

### Ошибка сложности {#oshibka-slozhnosti}

Код работает, но не укладывается в ограничения.

Действие: найти операцию внутри цикла, которая скрывает дополнительный множитель.

### Ошибка коммуникации {#oshibka-kommunikatsii}

Решение появляется в голове, но не объясняется последовательно.

Действие: записать двухминутное устное объяснение структуры, инварианта и сложности.

## Система подсказок {#sistema-podskazok}

Если застрял, открывай подсказки постепенно:

1. Название требуемой структуры данных.
2. Ключевой инвариант.
3. Псевдокод перехода.
4. Полное решение.

Записывай минимальный уровень, который потребовался. Решение после названия паттерна не считается полностью самостоятельным.

## Повторение задачи {#povtorenie-zadachi}

Сложную задачу повторяй:

- через один день;
- через одну неделю;
- через три недели.

При повторе нельзя смотреть старый код. Успех означает, что ты можешь заново вывести решение и объяснить его.

Если запомнился только текст кода, выбери другую задачу того же паттерна.

## Частые ошибки недели {#chastye-oshibki-nedeli}

1. Сначала угадывать паттерн, не формулируя brute force.
2. Решать задачи блоками с подписанными темами.
3. Смотреть решение после первых пяти минут.
4. Писать код до объяснения инварианта.
5. Называть сложность только по количеству циклов.
6. Проверять только пример из условия.
7. Не записывать полученную подсказку.
8. Считать задачу освоенной после одного просмотра решения.
9. Повторять только любимые темы.
10. Оценивать прогресс количеством задач без качества разбора.

## План недели {#plan-nedeli}

1. Составь скрытый набор из `8–10` задач.
2. В первый день реши две задачи без таймера и отработай процесс.
3. Остальные задачи решай с ограничением `40–45` минут.
4. Для каждой запиши brute force и сложность.
5. Сделай ручной trace до запуска.
6. Классифицируй ошибки по пяти категориям.
7. Повтори две самые сложные задачи через день.
8. В конце недели выбери темы для mock-интервью.

## Задачи для самостоятельного решения {#zadachi-dlya-samostoyatelnogo-resheniya}

Решай без названия паттерна и без просмотра связанных глав.

### Задача 1. Product of Array Except Self {#zadacha-1-product-of-array-except-self}

Для каждого элемента верни произведение всех остальных элементов.

Ограничения:

- нельзя использовать деление;
- требуется `O(n)` времени;
- дополнительная память, кроме ответа, должна быть `O(1)`.

Перед кодом объясни, какую информацию можно накопить слева и справа.

### Задача 2. Daily Temperatures {#zadacha-2-daily-temperatures}

Для каждого дня верни количество дней до более высокой температуры. Если такого дня нет, запиши `0`.

Начни с `O(n²)`, затем найди способ удалить кандидатов, для которых текущая температура уже стала ответом. Объясни, почему внутренний `while` не делает итоговую сложность квадратичной.
