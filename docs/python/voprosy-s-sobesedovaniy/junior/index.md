## Что такое PEP 8? {#chto-takoe-pep-8}

::: details Показать ответ
PEP 8 — руководство по оформлению Python-кода. Аббревиатура PEP означает *Python Enhancement Proposal*, то есть предложение по развитию Python.

Документ описывает соглашения, которые делают код единообразным и читаемым. Например:

- отступ в четыре пробела;
- правила размещения и группировки импортов;
- пробелы в выражениях;
- пустые строки между функциями и классами;
- правила именования переменных, функций, классов и констант;
- рекомендуемую длину строки.

PEP 8 не меняет синтаксис Python. Код может выполняться, даже если оформлен не по этим рекомендациям. При этом правила конкретного проекта имеют приоритет: если в проекте принята длина строки 100 символов, нужно соблюдать настройку проекта, а не механически применять предел PEP 8 в 79 символов.

Короткий ответ для собеседования:

> PEP 8 — официальный style guide для Python-кода. Он описывает отступы, именование, импорты, пробелы и другие правила оформления. Его цель — читаемый и единообразный код, но правила конкретного проекта важнее общих рекомендаций.

[Официальный текст PEP 8](https://peps.python.org/pep-0008/)
:::

## Какие типы данных есть в Python? {#kakie-tipy-dannykh-est-v-python}

::: details Показать ответ
В Python все значения являются объектами, а тип определяет, какие значения и операции поддерживает объект.

В таблице ниже перечислено `15` основных встроенных типов. Это учебная подборка типов, которые чаще всего встречаются в базовых вопросах по Python.

Основные встроенные типы можно разделить на группы:

| Группа | Типы | Пример |
| --- | --- | --- |
| Логический тип | `bool` | `True`, `False` |
| Числа | `int`, `float`, `complex` | `42`, `3.14`, `2 + 3j` |
| Строки | `str` | `"Python"` |
| Последовательности | `list`, `tuple`, `range` | `[1, 2]`, `(1, 2)`, `range(3)` |
| Словари (отображения) | `dict` | `{"name": "Ann"}` |
| Множества | `set`, `frozenset` | `{1, 2}`, `frozenset({1, 2})` |
| Бинарные данные | `bytes`, `bytearray`, `memoryview` | `b"abc"`, `bytearray(b"abc")` |
| Отсутствие значения | `NoneType` | `None` |

Как запомнить группы: `СЧТПКУБ` — **с**пециальные, **ч**исла, **т**екст, **п**оследовательности, **к**люч → значение, **у**никальные элементы, **б**инарные данные.

`dict` обычно называют словарём. В документации используется более широкая категория *mapping type* («отображение»): она описывает объекты, которые сопоставляют ключу значение, а `dict` является конкретным встроенным типом этой категории.

Это не закрытый список всех возможных типов. В программе можно определять собственные классы, а стандартная библиотека и сторонние библиотеки добавляют другие типы, например `Decimal`, `Path` или `datetime`.

Тип объекта можно проверить функцией `type()`:

```python
value = {"name": "Ann"}

print(type(value))  # <class 'dict'>
```

Короткий ответ для собеседования:

> В этой базовой классификации 15 встроенных типов: числа `int`, `float`, `complex`, логический `bool`, строка `str`, коллекции `list`, `tuple`, `dict`, `set`, а также `range`, `frozenset`, бинарные типы и `NoneType`. Кроме встроенных типов, можно создавать собственные классы.

[Встроенные типы в документации Python](https://docs.python.org/3/library/stdtypes.html)
:::

## Какие типы данных изменяемые, а какие неизменяемые? {#kakie-tipy-dannykh-izmenyaemye-a-kakie-neizmenyaemye}

::: details Показать ответ
Изменяемый объект можно изменить после создания, сохранив его идентичность. Для неизменяемого объекта операция с новым значением создаёт другой объект или возвращает уже существующий объект с подходящим значением.

Из `15` типов предыдущего ответа:

| Категория | Количество | Типы |
| --- | ---: | --- |
| Изменяемые | `4` | `list`, `dict`, `set`, `bytearray` |
| Неизменяемые | `10` | `int`, `float`, `complex`, `bool`, `str`, `tuple`, `range`, `bytes`, `frozenset`, `NoneType` |
| Зависит от буфера и режима представления | `1` | `memoryview` |

Большинство обычных экземпляров пользовательских классов тоже изменяемые, но они не входят в подсчёт встроенных типов.

Как запомнить четыре изменяемых типа: `ЛИДИСЕБАЙТ` — **ли**ст (`list`), **ди**кт (`dict`), **се**т (`set`), **байт** (`bytearray`).

Список изменяется на месте:

```python
numbers = [1, 2]
same_numbers = numbers

numbers.append(3)

print(numbers)       # [1, 2, 3]
print(same_numbers)  # [1, 2, 3]
```

Обе переменные ссылаются на один список, поэтому изменение видно через обе ссылки.

Строку изменить на месте нельзя:

```python
text = "python"
upper_text = text.upper()

print(text)        # python
print(upper_text)  # PYTHON
```

Метод `upper()` возвращает другую строку, а исходная остаётся прежней.

Неизменяемый контейнер может хранить изменяемый объект. Например, нельзя заменить элемент кортежа, но можно изменить список внутри него:

```python
value = ([1, 2], "python")

value[0].append(3)

print(value)  # ([1, 2, 3], 'python')
```

Сам кортеж по-прежнему содержит ссылки на те же два объекта, поэтому кортеж считается неизменяемым.

`memoryview` предоставляет доступ к буферу другого объекта. Представление над `bytes` доступно только для чтения, а представление над `bytearray` обычно позволяет изменять данные:

```python
readonly_view = memoryview(b"abc")
writable_view = memoryview(bytearray(b"abc"))

print(readonly_view.readonly)  # True
print(writable_view.readonly)  # False
```

Короткий ответ для собеседования:

> Среди 15 основных встроенных типов в этой классификации 4 изменяемых, 10 неизменяемых, а возможность записи через `memoryview` зависит от буфера и режима представления. При этом внутри неизменяемого `tuple` может находиться изменяемый объект.

[Модель данных Python: изменяемые и неизменяемые объекты](https://docs.python.org/3/reference/datamodel.html#objects-values-and-types)

[Бинарные типы: `bytes`, `bytearray` и `memoryview`](/python/yazyk-python/tipy-dannykh/binarnye-tipy-bytes-bytearray-memoryview)

## Что такое виртуальное окружение, зачем оно нужно и какие инструменты используются? {#chto-takoe-virtualnoe-okruzhenie-zachem-ono-nuzhno-i-kakie-instrumenty-ispolzuyutsya}

::: details Показать ответ
Виртуальное окружение — отдельное окружение Python для конкретного проекта. У него есть свой интерпретатор или ссылка на базовый интерпретатор и собственный каталог установленных пакетов `site-packages`.

По умолчанию пакеты из одного виртуального окружения не доступны в другом. Поэтому два проекта могут использовать разные версии одной библиотеки:

```text
project-a → requests 2.31
project-b → requests 2.32
```

Виртуальное окружение нужно, чтобы:

- зависимости разных проектов не конфликтовали;
- не устанавливать библиотеки в системный Python;
- удалять и пересоздавать окружение независимо от исходного кода;
- воспроизводить набор зависимостей на компьютере разработчика и в CI.

Минимальный пример со стандартным модулем `venv`:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install requests
deactivate
```

Для Windows PowerShell команда активации выглядит так:

```powershell
.venv\Scripts\Activate.ps1
```

Основные инструменты:

| Инструмент | Для чего используется |
| --- | --- |
| `venv` | стандартное создание виртуального окружения в Python |
| `virtualenv` | сторонний инструмент для создания изолированных Python-окружений |
| `uv` | создание окружений, установка Python и зависимостей, управление проектом |
| Poetry, Pipenv | зависимости, lock-файл и автоматическое управление окружением |
| Conda | окружения, версии Python и пакеты, включая зависимости не только из Python |

`pip` устанавливает пакеты в выбранное окружение, но сам по себе не заменяет инструмент создания окружения. Файл `requirements.txt`, `pyproject.toml` или lock-файл фиксирует зависимости; одно только окружение этого не делает.

Виртуальное окружение не является виртуальной машиной или контейнером. Оно не изолирует операционную систему, сеть и процессы, а разделяет прежде всего Python-интерпретатор и установленные пакеты.

Короткий ответ для собеседования:

> Виртуальное окружение изолирует интерпретатор и зависимости одного Python-проекта от других проектов и системного Python. Базовый инструмент — встроенный модуль `venv`; также используют `virtualenv`, `uv`, Poetry, Pipenv и Conda. Окружение не заменяет фиксацию зависимостей и не даёт изоляцию уровня контейнера.
